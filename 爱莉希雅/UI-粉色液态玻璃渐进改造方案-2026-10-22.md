# 爱莉希雅 UI 粉色液态玻璃渐进改造方案

日期：2026-10-22
状态：阶段 4 已完成自动验收；等待用户确认记忆库与关系图观感
正式项目：`F:\elysia\爱莉希雅`
回退基线：Git 标签 `ui-glass-baseline-20261022`，对应提交 `84c90b5`

## 1. 本次目标

在不改变现有界面分布、尺寸、交互逻辑和数据行为的前提下，统一提升所有可见界面的层次感与交互手感：

- 保留现有粉白、玫瑰色、淡紫色和爱莉希雅元素，不改成冷灰色通用玻璃风。
- 将目前较单薄的卡片、抽屉、弹层、输入区和小面板改成克制的粉色液态玻璃。
- 高频操作即时反馈，弹层出现与收起更顺滑，但不增加无意义的持续动画。
- 只使用基础 CSS；不引入 WebGL、SVG 滤镜、动画库或新依赖。
- 全部改动按阶段独立提交。任一阶段观感不合适，都可以只回退该阶段。

## 2. 明确不改的内容

- 不移动顶栏、侧栏、聊天区、输入区、抽屉、记忆库、账本和桌宠的位置。
- 不改变窗口尺寸、卡片固定尺寸、滚动方式、点击目标、快捷键、拖动区和 IPC。
- 不改聊天、记忆、关系图、账本、设置、Live2D 的数据与业务逻辑。
- 不重画现有背景图、头像、Live2D 模型和爱莉希雅图标。
- 不直接复制参考项目的 GPL-2.0 CSS；只使用其材质构成思路重新实现。

## 3. 从两份参考中采用的原则

### UI 交互

- 按下时立刻反馈：按钮和可点击卡片只做约 `0.97–0.985` 的轻微缩放或高光变化。
- 进入/退出使用短促的强 `ease-out`；界面内位移使用 `ease-in-out`。
- 高频 hover 和切换控制在约 `100–180ms`，弹层约 `180–240ms`。
- 不使用 `transition: all`，每条过渡明确写出属性。
- 动画优先只动 `transform` 与 `opacity`；禁止为视觉效果持续动画宽高、边距、定位或大面积阴影。
- 快速重复操作必须可打断；弹层不锁住用户等待动画结束。
- 提供 `prefers-reduced-motion` 降级，保留必要的颜色和透明度反馈，移除位移动画。

### 粉色液态玻璃

- 材质由四层轻效果构成：半透明粉白底、上缘高光、细粉色边界、低饱和投影。
- 只在需要和背景分层的主表面使用背景模糊，不在已模糊表面内部继续层层模糊。
- 玻璃厚度主要靠静态渐变与 `inset` 高光表现；装饰伪元素必须 `pointer-events: none`。
- 透明度必须保证正文、状态和危险操作仍清晰，不为了“像玻璃”牺牲可读性。
- 不照搬参考中的全局禁选、全局过渡、`filter: contrast(3)` 和多层动态模糊。

## 4. 统一但不改布局的视觉层级

| 层级 | 用途 | 处理方式 |
| --- | --- | --- |
| L0 背景 | 三张模式背景图、桌面透明区域 | 保持现状，不再叠加滤镜 |
| L1 外壳 | 主窗口、账本外框、快聊外框 | 淡粉透明底、细边界、单层外阴影 |
| L2 主表面 | 顶栏、侧栏、输入区、抽屉、弹层 | 比外壳更亮的粉白玻璃，有限背景模糊 |
| L3 内容卡 | 对话条目、任务、记忆、设置分组、账本数字卡 | 不再重复模糊，用渐变、内高光和小阴影分层 |
| L4 交互 | 按钮、标签、筛选、输入框、关系连线 | 明确 hover / active / focus / selected，保持命中区域不变 |
| L5 临时反馈 | 确认框、状态提示、加载提示 | 最高对比度、短动画、键盘焦点清晰 |

## 6. 每一阶段的回退与验收规则

1. 开始前确认工作区干净，并记录当前提交。
2. 一阶段只改约定界面，单独提交并推送；不和逻辑修改混在一起。
3. 自动检查至少包括语法、`git diff --check`、相关现有测试和 Electron 真实渲染。
4. 自动检查验证功能与布局；“玻璃是否自然、手感是否舒服”必须标为待用户人工验收。
5. 用户不满意时优先回退该阶段提交，不在错误方向上继续叠加覆盖。
6. 整体回退可回到 `ui-glass-baseline-20261022`；该标签不得移动或覆盖。
