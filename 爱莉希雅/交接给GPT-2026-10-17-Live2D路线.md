### 1.4 MCP 接入的四个坑（每个都能卡半天）

1. **令牌**：`HKCU\Software\JavaSoft\Prefs\io\github\psd2live\agent` → `agent_mcp_bearer_token`，
   值是 `r4diw/C/D/Dm/...` 这种形式 —— **把 `/` 全删掉才是真令牌**，带着斜杠怎么试都 401。
2. **HTTP body 必须发 UTF-8 字节**：直接传字符串会把中文路径变成 `F:/elysia/????/??/`，
   报 `Illegal char <?>`。用 `[System.Text.Encoding]::UTF8.GetBytes($json)` 且 `charset=utf-8`。
3. **参数包装不统一**：绝大多数工具的 `arguments` 是 `{request: {...}}`；
   但 **`workspace_call` 例外**，`operation` 在最外层（`{operation, request}`）。
4. **`.ps1` 必须带 UTF-8 BOM**：本机是 PowerShell 5.1，无 BOM 的 UTF-8 脚本会按 GBK 读，
   中文全乱、语法报错。

## 3. 当前困难（重点）

### ★ 困难一：眨眼不合格 —— 缺闭眼素材，这是主要卡点

**根因（有图为证，不是推断）**：PSD2Live 在没有闭眼素材时，"眨眼"是把
**虹膜 + 睫毛竖着压扁**。工程里查实：

```
eyewhite   ★ 缺失      （See-through 的 caption 里有，但这张图输出是空层）
eye_close  ★ 缺失      （See-through 根本不产出）
irides     有（2）
eyelash    有（2）
```

定点证据：`.cache\p2l\眨眼\poses-1.png`（睁/半闭/闭）、`levels-1.png`（1.0/0.5/0.25/0.1 四档）。
**四档没有一档能看** —— 不是"闭太深"，是根本不具备闭眼条件。

**DSH 已经做成的部分**：

- 用户手绘了两条闭眼线；DSH 用**两只虹膜当锚点**求出「用户图 → 1280 画布」的
  缩放 0.3387、虹膜中心 r=(579,348.5) l=(712,378)，把线换算进画布坐标，
  拟合二次曲线重描成干净笔画，产出 `eye_close_l.png` / `eye_close_r.png`
  （在 `SeeThrough-v2\图层\_闭眼试验\`，曲线坐标在 `.cache\p2l\眨眼\闭眼线.json`）
- **已验证：`role=eye_close` 是被程序认的，且会跟着 `ParamEyeLOpen` 自动显隐**
  （睁眼时看不见、闭眼时出现）—— 见 `.cache\p2l\眨眼\clean-1.png`

**卡住的地方**：闭眼时**虹膜和压下来的睫毛仍然露着**，所以闭眼那一帧还是脏的。

**两条试过并失败的路（别重走）**：

1. **把闭眼层做成"肤色填充 + 睫毛线"**，想直接盖住虹膜 →
   结果是把**两块肤色方补丁贴在脸上**，边界清晰可见。
   现场：`.cache\p2l\眨眼\闭眼填充-核对.png`。**程序化补画精度不够，必须真画。**
2. **给 `irides` / `eyelash` 设 `type=toggle, parameter=ParamEyeLOpen` 差分**
   （`workspace_call` → `layer_classify`，4/4 调用返回 ok=True）→
   结果**睁眼时睫毛整条消失、闭眼时闭眼线也不出现**，比原来更糟。
   `toggle` 的开关方向或 `switch_id` 语义与假设不符。
   （`type` 合法值：`preset | toggle | switch`，来自 `workspace_get_operation`。）

**建议给 GPT 的正确做法**：

- 路线 A（最确定）：请用户/画师画一版**真正的闭眼素材**——闭眼睑 + 眼窝阴影 + 睫毛，
  **覆盖到整个眼框**，直接当 `eye_close` 层用。
- 路线 B（代码路线）：**不要猜差分语义**。在 GUI 里手动给任一层设一次"由 `ParamEyeLOpen`
  控制"，然后用 `workspace_inspect scope=layers` 读回它的 `type / parameter / switch_id`，
  照着抄。
- 无论走哪条，**`eyewhite` 都该补**：现在虹膜是直接贴在脸上的，没有眼白托底。

### ★ 困难二：没有能在播放器里看的演示

- `motion` 工具的 `seed_builtin`（内置名首字母大写：`Idle` `Blink` `Nod` `Shake` `TailSwing`…）
  **能成功把动作种进工程**（工程里出现 `motion_1 / Blink`）；
- 但 `export_target target=gif settings.clip=Blink` 报
  **`Unknown clip: Blink. Clips: none`** —— 动作片段与导出编译的 clip 列表是两套，没接上；
- `project/import_cmo3`（要 `mode` + `state`）导入成功，但**动作没跟进来**，仍是 0。

**结论**：MCP 导出的 GIF 只有呼吸 + 物理的"身体微摆"，**看不到眨眼**。
眨眼只在 CLI 生成的那套 `.moc3` + `.motion3.json` 里存在。

**建议**：把 `SeeThrough-v2\模型\` 挂到网页播放器（`export_target` 的 `web` 目标或 p2lrt）
或 VTube Studio，眨眼/点头/摇头就能当场看见 —— 这是最快能让人看到成果的一步。

### 困难三：PSD2Live 长跑会静默退化（重要环境坑）

中途出现 **`变形器 0`**（正常 28），**连原封不动的清单也能复现**。
`Stop-Process PSD2Live` → 重新启动 → 立刻恢复 28。
**长时间反复导入 / 导入 cmo3 / 种动作之后，绑定生成会静默失败且不报错。**
看到"参数没反应、变形器 0"，**先重启再查别的**。

### 困难四：栅格预算

`create_artwork` 有总栅格预算：全画布 3 倍 × 3 层 = 42 MP 被拒
（`Artwork exceeds total raster budget`）。
现在的做法是**每层裁到 alpha 边界 + 用 x/y 摆位**，v2 合计只有 2.89 MP。
每层 α 边界与 x/y 都记在 `图层清单.json` 里，可直接复用。

### 困难五：See-through 的出品质问题

- 24 个 caption 里只有 17 层有像素，其余是空层（含 `eyewhite`）；
- 有误标：`tail`（尾巴）其实是**一缕头发** —— DSH 已在 `拆PSD.py` 的映射表里纠正为 `back_hair`；
  `handwear` 把手臂和一缕头发装在一起；
- 画布只有 1280（Space 的 `resolution` 提到 1280 已是当前可用的较高档）。
