# C-12 纯本地假渠道适配器

日期：2026-10-25。实现：`脑/假渠道适配器.cjs`。依赖：仅`脑/渠道契约.cjs`。

用途：让C-11的四个适配器接口可以用虚构消息实际调用，验证字段、异步结果、订阅与取消行为，为后续权限和路由开发提供可控测试入口。所有数据只在实例内存中，关闭后释放收件和任务正文；没有网络、文件、模型、真实账号、后台计时器或生产接线。

## 创建与基础接口

```js
const { 创建假渠道适配器 } = require('./脑/假渠道适配器.cjs')
const 假渠道 = 创建假渠道适配器()
```

构造选项：`能力`为完整C-11能力对象；端点渠道必须是`fake`，默认账号`local-fixture`；`取现在`为返回有效Date的同步测试时钟，默认真实当前时间。测试时钟必须始终有效，不承担生产校时功能。

| 接口 | 行为 |
|---|---|
| 取能力() | 返回契约合法的能力独立快照；修改快照不会改变实例 |
| 订阅接收(处理) | 注册一个订阅，返回幂等的取消订阅函数；相同函数可以独立订阅多次 |
| 发送(消息, {中止}) | 返回Promise，结果符合C-11；格式无效时拒绝Promise |
| 取消(请求) | 返回目标任务的结果；端点、会话和操作者须与目标相符 |

默认能力是本地模拟值：回复和取消supported，主动发送和流式unsupported，正文上限2000，无附件，回复窗口unlimited。不能据此推断QQ或其他平台的真实权限。

订阅接收本身不会调用模型或生成回复。需要模拟一个回环时，测试代码可订阅消息并显式调用发送，使用固定虚构回复；这样的回环不表示现有对话核心已接入。

## 测试控制入口

| 接口 | 行为 |
|---|---|
| 注入接收(消息) | 校验后交给当前订阅者；返回通知数、失败数与固定错误码 |
| 排入场景(场景) | 为下一次通过发送前检查的发送设置结果：sent、failed、unknown或manual |
| 完成发送(请求编号, 场景) | 明确结束一个manual任务；场景为sent、failed或unknown；不存在时返回null |
| 设连接(boolean) | 模拟断线和恢复；不建立真实连接 |
| 设能力(完整能力) | 替换能力快照，端点不可改变；暂缓任务完成前再次检查能力 |
| 取观测() | 返回实例类型、连接/关闭状态、订阅数、注入数、发送尝试数、模拟送达数与待完成数 |
| 取发送记录() | 只返回已执行任务的契约回执副本，不含消息正文、附件、原始异常或身份映射 |
| 关闭() | 幂等关闭，取消尚未交付的manual任务，移除中止监听器、订阅和场景，释放收件/任务正文；不可重开 |

注入接收会给每个订阅独立副本，并隔离同步抛错和异步拒绝；其他订阅仍有机会收到。报告不会透传异常原文。取消订阅及关闭影响后续事件，不强行停止已经进入用户回调的代码。

发送前拒绝的请求不消耗预设场景，也不计入发送尝试数；只有真正进入本地场景模拟的请求计数。模拟送达数只统计sent的确认次数，unknown计数为零不代表真实网络中“确定未送达”。这些观测不是生产审计日志。

## 结果、窗口与取消

- sent生成`fake-ack-N`；failed表示模拟确定未交付，返回SEND_FAILED且可重试；unknown返回DELIVERY_UNKNOWN且不可自动重试。适配器没有重试任务。
- manual在模拟交付前等待显式完成，没有后台等待计时器。完成时重新检查当前能力、截止时间与连接。
- 回复/主动能力未知或不支持、正文/附件超过当前能力，返回CAPABILITY_UNSUPPORTED；截止时间已到返回EXPIRED。
- 有限回复窗口从注入消息的原始发生时间计算，且核对会话、发送者和回复编号。来源缺失/时间未知拒绝；重放消息不改写第一次保存的发生时间。窗口未知时不猜测可用。
- 默认unlimited仅用于测试，不要求先注入来源；它也不证明任何真实账号、联系人或会话获得授权。
- 显式取消只作用于目标相符的任务；仍在manual且取消能力supported时返回cancelled。已sent或unknown的结果保持原样，不伪装成撤回。
- AbortSignal用于本地尚未交付任务的中止；不会把信号reason带入回执。预先中止不创建任务，完成后移除监听器。平台取消能力与本地中止分别模拟。
- 断线时manual明确尚未交付，因此结束为CHANNEL_OFFLINE；恢复后不自动补发。关闭同样只结束尚未交付任务，保留已有sent/unknown回执供测试观察。

## 与C-13至C-15的分界

重复注入会再次通知订阅者，并保留同一个C-11去重键。这是为了让后续去重层能够真实接受重放输入；本模块不做接收去重。

任务表仅用于本地完成和取消模拟：同一编号的并发发送拒绝，不能覆盖尚未完成任务；历史同编号更换目标或载荷也拒绝，字段顺序变化不视为载荷改变。已结束后显式再次调用相同发送会产生新一次模拟尝试，不是生产发送幂等保障，调用方必须遵守先检查结果和重试策略的规则。

没有本人白名单、跨渠道身份绑定、核心对话映射、持久去重、重试退避、速率限制、登录重连或账号权限。取消时匹配操作者与目标是测试一致性检查，不是真实身份认证。C-13实现权限，C-14实现会话映射，C-15实现实际队列和去重；这些不能提前标为通过。

本地发送格式仍使用C-11白名单，private与额外凭据字段在进入任务表之前被拒绝。正文是否来自private仍由已有外发闸门和后续来源控制保证，不能用一个shared标签代替。

## 最小演示

使用`tools/fixtures/渠道契约-v1.json`的虚构样例，端点转换为fake后：

```js
const 样例 = require('./tools/fixtures/渠道契约-v1.json')
const 端点 = 假渠道.取能力().端点
const 停止 = 假渠道.订阅接收(async (收到) => {
  const 回执 = await 假渠道.发送({
    ...样例.普通回复, 端点,
    请求编号: 'demo-' + 收到.消息编号,
    回复消息编号: 收到.消息编号,
    正文: '这是本地固定测试回复。',
  })
  console.log(回执.状态) // sent；只代表本地模拟
})
await 假渠道.注入接收({ ...样例.本人私聊, 端点 })
停止()
假渠道.关闭()
```

演示在异步函数内运行；不把假适配器装到正式入口。专项命令：`node tools/测假渠道适配器.cjs`。测试包含短看门狗，避免悬空Promise导致Node提前退出；这只属于测试脚本，不是适配器后台任务。
