# 测试说明 —— 怎么跑，哪几个红是正常的

> 给**下一个跑测试的人**看的（很可能还是我自己）。
> 看到一片红先翻这一页，能省掉半小时的"这是不是我刚改坏的"。

---

## 怎么跑一个

```
node tools\测学习任务.cjs
```

记忆日记的数据与调度固定回归可以直接运行：

```powershell
npm run test:diary
```

它只使用系统临时目录和假模型，不读取或修改真正的 `记忆\`。

断言型测试末尾会打 `N / N`：**全过退 0，有一格不过退 1**。

## 工具层固定离线回归

搜索、读取、写入、命令产物和统一回执改动后，优先跑这一条：

```powershell
npm run test:tools
```

它串行运行 12 个确定性脚本，共 227 项；使用 `F:\elysia\_测试` 下的隔离数据并在结束时清理。
搜索全部使用假响应，不读取真实 SerpAPI Key；也不调用 DeepSeek。任何子脚本退出非零或没有
可核对的 `N/N` 汇总，整套都会退出 1。它是阶段 C+ 的日常固定入口，不替代界面人工验收和
发布前完整回归。

## 怎么跑全套

在当前唯一开发目录 `F:\elysia\爱莉希雅\` 下：

```powershell
Get-ChildItem tools\测*.cjs | Sort-Object Name | ForEach-Object {
  $o = (& node $_.FullName 2>&1 | Out-String)
  "{0,-26} 退出{1,-3} {2}" -f $_.Name, $LASTEXITCODE, (($o -split "`r?`n" | Where-Object { $_ -match '/\s*\d+' } | Select-Object -Last 1))
}
```

旧环境曾出现 Node 子进程被沙箱拦截；当前本机固定工具回归已可由
`tools\测工具可信.cjs` 串行编排。全套历史脚本仍可使用上面的 PowerShell 命令。

# 三类"正常的红"

## 一、环境性的：在这台机器上永远红

| 测试 | 卡在哪 |
|---|---|
| `测工作区.cjs` | 要往 `D:\` 根目录建目录 → EPERM |
| `测启动子进程.cjs` | 起子进程 → EPERM |
| `测试键盘监听.cjs` | 装全局键盘钩子 → EPERM |

**要看真实结果，得在他自己的终端里跑这几个。**

## 二、非确定性的：真调模型，它发挥不好就掉一格

| 测试 | 它干什么 |
|---|---|
| `测整条线.cjs` | 真让她写一个 C 程序，再看那份代码立不立得住 |
| `测子代理.cjs` | 真派一个子代理去读文件、交一张纸条回来 |

**红了先原样重跑一遍**，两次都红才是真有问题。
（这两个要花钱，别闲着反复跑。）

> 2026-10-08 亲眼见过：`测整条线` 一次 1/4、立刻重跑 10/10；
> `测子代理` 一次 30/31、重跑 31/31。两次都是模型的发挥，不是代码。

## 三、不是断言型的：打什么输出都正常

`测表情` / `测动手` / `测环境事实` / `测捞价` / `测模型` / `测飘不飘` /
`测数进程` / `测网络` / `测温度` / `测两层温度` / `测一轮多写` / `测一整轮` /
`测账本` / `测搜索`

这些是**探测脚本**：跑一遍、把量到的东西打出来、给人看。

`测两层温度.cjs` 打 `0 / 0` 是正常的 —— 它一格断言都没有，
它只是各写一份代码给你自己拿去编。

# 写新测试的几条规矩

都是踩出来的，照着做能少挨几刀。

### 1. 退出码要说实话

```js
process.exit(过了 === 总数 ? 0 : 1)
```

`测并发确认.cjs` 曾经跑出 `8 / 15` 还退 0 ——
于是在"跑全套"里它跟通过的长得一模一样，**红了整整一天没人发现**。

### 2. 别碰真目录

用环境变量把目录指到 `.cache\_测xxx\`：

```js
process.env.ELYSIA_附件目录 = 测试目录   // 必须在 require 之前设
```

已开的口子：`ELYSIA_附件目录`、`ELYSIA_任务文件`、`ELYSIA_学习区`、`ELYSIA_进度文件`。

**并且在开头给真目录拍张快照**，结尾比对 —— 那才是"没碰真目录"的真凭据。
（`测附件.cjs` 就是这么干的。它原来写的是 `!fs.existsSync(...) || true`，
恒真，等于没查。）

### 3. 替身要照着真身的形状做

`测并发确认.cjs` 吃过两次这个亏：替身返回的形状跟 `main.js` 真身不一样，
于是"全过"是假的，真机上照样卡住。

**程序那边改了返回值，先把所有替身搜一遍。** 搜什么：
调用它的地方、断言它的地方 —— 后者常常被忘掉。

### 4. 收网要放在 `finally` 里

换掉 `fetch` 之后忘了换回来，后面的测试会静默走兜底路径，
量出来的东西全不对，而且不报错。

### 5. 测"安静地做错"的事

最值得写测试的不是"功能通不通"，是**那种不报错但结果错了**的：
名字没洗、文件被盖掉、别人的备注被抹掉、权限被悄悄改掉。
这些没人测就永远发现不了。

`测学习任务.cjs` 里最值钱的一格就是
"他自己写在清单里的那句备注还在吗" —— 它真抓出过一个会抹掉他笔记的 bug。
