## 当前代码的具体缺口

1. `脑/模型连接.cjs` 的异步路径在内部生成请求 UUID，先通过 `绑定异步记录` 发送仅含请求号/模型/状态/代码/用量的 started 事件，再调用 HTTP；核心无法在此之前可靠保存该 UUID 和轮次之间的关系。
2. 同一回调的 succeeded 事件只含用量，不含已验证的回复正文。即使用量成功落盘，进程在交还正文前退出后，也没有可恢复的结果。不能通过独立提交用量和结果来冒充同一事务。
3. `core/异步用量.cjs` 使用 Worker 异步读快照、构造计划及提交；现有 `状态.保存快照组` 自行启动事务。`storage/sqlite-state.cjs` 的内部读写可在既有受控事务中复用，但需要专门的受限领域规则与同事务回执，不能嵌套调用现有公共保存接口。
4. 格式3的 `轮次执行.标记可能发送` 有持久状态和乐观版本；Worker 对同操作编号回放历史回执。`回放:false` 只是一次响应的标识，本身不是不可复制的发送权。恢复后的格式3库有隔离标记，必须继续拒绝写入与发送。
5. 同一个 SQLite 事务无法包括远端 HTTP。可能已发送但未获得或未保存结果时，不能推断远端是否接收或收费；重启、超时、回执丢失和旧备份恢复都不能据此自动补发。

## 选定协议：数据库保守状态 + 进程内一次性能力

使用显式新路径，不改动已有同步连接、旧异步绑定的默认语义。请求 UUID 必须在数据库预留之前生成，并由受信层传给新路径；严格检查 UUID、模型、轮次身份和预算，不接受来自任意聊天文本的编号或任意模型地址。

1. **预留与 started**：Worker 在一个事务内对轮次唯一键/内容指纹进行占用，绑定请求 UUID 与模型，并追加对应 started 用量，连同 Worker 操作回执一起提交。相同轮次但不同内容/模型冲突；返回已有记录不是发送许可。started 仅是本地事件，不能推断发送或计费。
2. **可能发送**：受信调度器提交 `reserved → dispatch_possible` 并等待首次确认；同轮次只允许一次状态转移。持久状态在发 HTTP 前成立，崩溃于提交后、实际调用前时也按可能已发处理，优先避免重复收费，可能需要后续人工处理。
3. **一次性能力**：只有本进程中发起该次转移且收到**本次非回放确认**的受信调用链，才能创建一个不可序列化的内存能力；绑定轮次、UUID、模型、拥有者/Worker 世代和预算，拒绝跨连接、伪造、复制重放或两路并发。能力在调用假 transport 之前同步消费，消费后永不再次生效。将状态存档、重新查询回执或恢复 Worker 都不能重建能力。能力仅约束受信代码，不是网络供应商侧幂等保证。
4. **世代和取消**：发送前最后一个异步等待之后，检查连接未关闭、中止信号、Worker 当前世代与能力归属；在同一 JS 同步执行段消费能力并调用注入的 transport。若回执未知/回放、Worker 世代改变、调用方失去原始能力、取消或超时，能力不得发放或使用；若可能发送状态已提交，留待核对而不是回退。能力不能跨线程、通过 IPC 传给不受信端或写入回执/数据库/日志。
5. **结果与 succeeded**：HTTP 成功且响应/正文/用量完整验证后，在一个 Worker 事务中校验请求关联及 `dispatch_possible` 版本，写入暂存结果、更新轮次为 `result_ready`、追加 succeeded 用量，并写无正文 Worker 回执；只有事务确认后才能交付回复。正文按原共享聊天的隐私边界限定，最多 8000 JS 字符、32000 UTF-8 字节且整个 JSON 不超过 Worker 输入上限；不得截断伪造成完整结果。缺失 usage 保留 null，不算作零费用。
6. **未知及关闭**：网络失败或取消、结果事务回执未知，禁止在同一轮追加两个互斥终态；对事务未知先查持久状态及操作回执。能够明确写 unknown 时按固定安全代码记录，不能写入密钥/请求体/响应正文。请求可能已发送但无已落盘结果时保持待处理，不自动请求；关闭先停止发放能力，再中止等待并排空已开始的写事务，不能把连接同步关闭描述为已停止落盘。

 Worker 回执仅供查事务结果，单独的用量事件和 `dispatch_possible` 不等于响应已保存；恢复后只读既有状态/结果，不重新创建发送能力。版本冲突必须拒绝覆盖，不能用新计划悄悄重试；同次写入失败回滚轮次、用量及回执。

## 状态和故障矩阵

| 观察到的情况 | 行为 |
| --- | --- |
| 预留/started 明确未提交，尚未获得发送能力 | 可由新的受信尝试重新执行本地事务；不能声称曾向远端发送 |
| 预留或状态提交未知 | 封闭本次执行，先查回执与领域状态；不存在记录也不能证明远端没有收到旧备份之外的请求 |
| `dispatch_possible` 已提交，能力丢失或回执重放 | 视为可能已发送，不重新发放发送能力 |
| 已验证结果+用量同事务成功 | 返回该已存结果；后续聊天提交仍需单独事务与版本校验 |
| 结果事务未知或失败 | 不返回成功、不生成第二终态、不自动重发；查询回执并保留不确定状态 |
| 已恢复的旧快照、损坏状态、备份回滚 | 当前恢复库继续隔离业务写入；不推断可以重发 |

实际用户主动要求新一次付费请求时的提示、身份与授权、保留期限和恢复界面另行设计；本阶段没有开放真实网络重试。旧 C2 的模型连接和用量数据缺关联，不因部署代码而被认定为新协议记录。
