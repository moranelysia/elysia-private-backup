# S-16D3 C3B：轮次状态隔离盘库与 Worker 接入方案

状态：仅完成现有实现核对与设计，未实现磁盘格式、命令或迁移。目标为新建的虚构临时隔离库；不打开、覆盖或迁移正式库，C3C 的模型/用量接线及 C3D 的聊天事务均不在本步骤内。

## 核对后的约束

1. `sqlite-disk.cjs` 当前 SQLite `user_version=2`；`disk_storage_format` 分别为 `1`（原磁盘）或 `2`（带 Worker 回执）。打开时会按内存组合仓储生成的 schema 列表严格比较，先只读核验，再重开读写；`save()` 目前只保留格式 2，其余均写为 1。新增表后必须处理版本和 schema 模板，不能直接把 3 写进现有逻辑，否则可能错误降级。
2. 当前 C3A 仓储明确拒绝磁盘和本机影子上下文；自身的建表逻辑能初始化内存表，但不能直接用于只读预检，也不应在打开已有磁盘时自动补表。应分离共享的校验/状态转移与仅新建时初始化，保留现有内存范围检查。
3. `sqlite-backup.cjs` 的逻辑快照按组合仓储初始化时捕获的表及 schema 指纹恢复；旧格式没有新表，也不包含 Worker 的磁盘私有键。把 C3A 表临时附加到已有仓储后，既不能保证旧组合句柄的校验通过，也不能把旧逻辑备份称为包含完整新状态的续跑备份。
4. Worker 的写命令在事务提交前写入运行回执，返回值必须有 `好:true`。C3A 返回的是摘要而没有此字段；重复操作编号会直接重放历史结果。且目前回执将完整返回值持久化，不能让暂存正文作为写回执的返回结果。
5. Worker 协议输入上限 65536 字节、结果上限 262144 字节；队列、超时和回执容量有界。C3A 结果上限为 8000 JS 字符及 32000 UTF-8 字节，还必须在完整 JSON 编码后的消息大小上验证，不能只按正文原始字节推断。

## 范围和格式选择

优先采用显式的新虚构用途和新格式，例如 `synthetic-turn-disk-v3`、`user_version=3`、`disk_storage_format=3`，具体名称在实现时固定并统一校验。新格式应在新建时就包含完整表、版本元数据及空 Worker 回执；marker、数据库头、元数据及 schema 模板须互相一致。不能仅加一个版本号：目录/文件身份、只读预检、WAL、锁、所有权与事务规则沿用并重新验证。

旧用途与旧版本仍走既有代码路径和原样测试；旧库不会因为启动新版本而改写、迁移、重建或静默升级。新入口不接受旧逻辑包或现有目录作为初始来源；旧库与不兼容包应明确拒绝，未来迁移另做方案。两套版本的显式识别必须贯穿只读与读写打开、模板、元数据保存、监督器恢复与 Worker 启动，任何组合不一致均拒绝。

先为新格式建立版本化组合仓储和空的隔离轮次表，明确组合仓储核验时机；不要在仓储捕获 schema 指纹之后再附加表。按虚构 shared 测试范围拒绝 private、本机影子及正式路径；字符串标签本身不能证明正文没有敏感信息，真实数据接入还需独立的授权和隐私设计。

## 固定命令与回执

隔离 Worker 增加有限的轮次命令：预留、读取元数据、标记可能发送、标记未知、暂存结果、受限读取暂存结果、模拟完成。每条命令使用严格字段、角色范围和固定大小上限，无任意 SQL、路径、网络、回调或脚本能力；状态、请求 UUID、指纹、版本校验与 C3A 一致。模拟完成只验证状态机，绝不能被当作聊天与记忆已事务提交；C3D 才实现真实组合事务。

所有写命令结果均为 `好:true` 加不含正文的受限摘要，领域状态变化和运行回执处于同一事务；读取暂存正文只能经单独的受控只读命令，不能出现在写回执、运行日志或默认聊天/记忆导出。摘要中的哈希和请求号仍是关联信息，不视为匿名化。结果和调用参数不能进入错误文本。回执、数据量或队列满时拒绝，不能通过删除防重记录自动腾位置。

**防重复发送的额外要求：**原 Worker 对同一操作编号会重放既有成功结果；因此“标记可能发送成功”的回执不得直接被理解为可以重复发 HTTP。C3B 只验证存储，不提供发送入口。C3C 接线前必须设计受信调用方的一次性发送权：首次持有者、回执重放、响应丢失、调用方/Worker 重建及并发争用都要有可区分的行为；重放或持有者状态不明只能封闭，不得靠重新领取历史回执发送。领域状态/数据库事务只能约束受信本地代码，不能保证供应商侧恰好一次。

## 备份、恢复与删除

先定义新版逻辑快照/恢复器，包含新表与格式指纹，并核对已完成记录及未完成状态；与旧格式的原文导出分开，暂存正文不得混入旧原格式导出。是否允许新格式逻辑备份包含暂存正文，应根据虚构测试显式声明，不得默认把它描述为生产隐私策略。旧 v5 包及既有 Worker 回执并不组成新格式完整续跑包，拒绝误用。

物理备份、WAL/附件一致屏障与生产恢复是 S-16E 的独立工作；本轮最多验证虚构逻辑备份和受控新库恢复，不假称完成物理备份。恢复较旧备份可能丢失已请求证据；恢复后的来源世代不能证明不回滚时，必须标为隔离，不得因记录不存在而自动发送。删除暂存正文和最终删除对话仍需保留必要防重墓碑；具体真实数据保留时限和隐私策略须在生产接线前另行落实。

## 实施顺序与验收

原 C3A → 单项 C3B磁盘/Worker → C3C 调整为以下子步，每步结束更新共同协作和步骤账本：

| 步骤 | 范围 | 完成标准 |
| --- | --- | --- |
| C3B1 | 分离状态机的 schema、虚构内存初始化与事务内可复用操作；不接磁盘或 Worker | C3A 原行为回归；禁止手工嵌套事务，外层回滚整体生效；不提前开放磁盘 |
| C3B2 | 显式新格式虚构盘库、只读模板与版本化组合；不接新 Worker 命令 | 新建重开、旧格式未改变、版本/表/元数据错误拒写；无生产路径及旧库隐式迁移 |
| C3B3 | 新格式 Worker 固定命令、元数据回执及异步门面 | 回执与状态同事务、重复及竞争、容量、正文不入回执、关闭和提交前/后真实终止 Worker；旧 Worker 回归 |
| C3B4 | 虚构逻辑快照和受控恢复，检查新旧格式与备份回滚边界 | 新表及不确定状态不丢失，旧包/格式不误当新续跑包，损坏和缺表拒绝；明确不覆盖真实数据或物理备份 |

C3B4 后先重新评估一次性发送权与 C3C 的用量/结果事务；C3D、C3E、D4 和部署仍后置。每步运行专项和相关回归，人工验收只在存在需用户判断的界面或操作时安排。
