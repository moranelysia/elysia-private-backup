## 已核实的限制

- `core/异步假对话核心.cjs` 的轮次标识由渠道、发送方、消息编号及内容指纹构成，成功聊天可通过 Worker 回执查到；回执中没有保存轮次到模型请求编号的映射。模型成功后但聊天未提交时，重启无法安全地判定该轮是否已请求。
- `脑/模型连接.cjs` 在开始记账前内部随机生成请求 UUID；`core/异步用量.cjs` 的事件只有请求编号、模型、状态、代码、用量，不含聊天轮次或结果正文。started 已提交不代表 HTTP 已发送；网络结果丢失时也不能推断是否收费。
- Worker 的运行回执上限为 2048 条、1 MiB；达到上限是拒绝写入，不是无限期历史库。用量快照也有 10000 条及消息大小约束。不能把任一现有上限当成永久去重机制，也不能按回执缺失断言请求未发送。
- `sqlite-disk.cjs` 对磁盘 schema 做严格匹配并核验版本；新增表涉及 schema 版本、备份/恢复及旧格式兼容，不能只运行 `CREATE TABLE` 后声称可迁移。数据库事务无法与外部 HTTP 原子提交，也不能单凭本地数据保证供应商只处理一次。

## 本方案的选择和数据边界

选择在同一隔离数据库引入**轮次执行记录**，与用量记录及聊天事务建立可核对的关联；成功响应先暂存受限结果，再在原有版本和记忆开关校验下提交聊天。相比只记录一个“曾请求”标志，这样能恢复已经落盘的结果，但会增加临时正文存储及数据库空间占用。首版只用于持久化 shared 对话，私密日记、临时/无痕对话、工具原文、凭据和系统提示不得进入结果暂存；不把正文放入用量账本或 Worker 运行回执。

暂存结果至少受与正式聊天正文相同的目录权限、备份、导出和删除边界约束；不能宣称加密或隐私隔离已经实现。按现有模型输出及 Worker 消息上限设硬上限，拒绝超限，不截断伪造成完整结果；给暂存正文定义明确清除时机、删除对话级联规则和容量告警。正文清除不得删除必要的已请求墓碑或放开重试。暂存和墓碑的具体保留时限、备份暴露范围在接入真实数据之前另行确定，本阶段不自行清除真实内容。

## 状态与原子边界

1. **身份与冲突**：以受限渠道/账号/会话/消息标识映射到稳定轮次键，另存原始消息内容指纹，数据库唯一约束阻止重复占用；同键不同指纹明确冲突。轮次键和指纹不作为匿名化证明，错误与日志不输出输入正文、凭据或模型响应。
2. **预留**：Worker 用事务插入唯一轮次、请求 UUID、模型及版本信息；提交确认前不允许请求。核心可预先分配并显式传入 UUID，或在事务回执后交给连接，具体接口必须保持 UUID 唯一性与预算校验。第一次开始记录与该关联必须由同一事务完成，或由经过验证的事务协议保证任何可发送路径都已有持久关联；原有 `异步用量` 整快照不能直接声称与新表原子。
3. **可能已发送**：在调用 HTTP 之前持久写入 `dispatch_possible` 并等待确认。它只表示“可能发出”，即使实际上在调用前崩溃也不得自动重发。进程、Worker、队列和连接的所有取消/超时都不能把它推回可自动发送状态。
4. **结果已落盘**：接收并验证响应后，用一次事务保存有界结果、请求关联和 succeeded 用量；只有事务确认后才向核心交付结果。若结果处理时崩溃、写入超时或远端结果缺失，保留不确定状态，不伪造失败或零费用，不自动请求。若事务未知，先恢复 Worker 并核对领域记录和回执；查询缺失并不能单独证明未发送。
5. **聊天已提交**：在同一事务核验会话版本、记忆版本与开关，保存聊天、允许的记忆标记，并将轮次标记为完成。提交前后断连时查轮次领域状态及回执；重放必须复查现有记忆开关约束。成功后按规定清除暂存正文，保留防重依据。
6. **不确定或冲突**：`dispatch_possible` 但无已落盘结果、unknown 用量、结果落盘但版本/开关发生不兼容变化，均进入受限恢复/待处理状态；不得自动重新调用模型、自动覆盖版本或把未知结果当成失败。对已有结果的应用须重新验证身份、版本、记忆开关；冲突时保留结果并停止，不能悄悄生成新回复。用户主动决定重试的界面、收费提示与授权语义后续单独设计，本阶段不开放真实请求重试。

## 重启与备份回滚

重启时先恢复独占 Worker、验证数据库和领域状态；按轮次查记录，读取成功的已保存聊天或可用暂存结果。不确定或状态损坏必须封闭该轮；Worker 回执只能辅助判定数据库事务，不代表网络侧状态。正常进程重启与 SQLite crash recovery 要分开测试，不能以正常关闭代替断电/终止测试。

旧 C2 数据和迁移前数据没有可靠映射，不能把“记录不存在”解释为“未发出”；首版只允许新建的虚构隔离库进入新协议。将旧库迁入生产之前须另行制定兼容基线及保守隔离规则。恢复旧备份可能回滚已经发出请求的本地证据；除非另有独立且可信的不回滚证据，恢复后的未完成/可能关联旧请求轮次应隔离，不能自动重发。此方案不保证旧备份回滚或供应商侧跨故障恰好一次。
