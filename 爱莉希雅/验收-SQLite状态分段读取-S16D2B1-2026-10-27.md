# S-16D2B1 状态分段读取验收

日期：2026-10-27；基线 `14020b9`。实现提交见共同协作和步骤账本。

此前实测，已存在的状态超过 Worker 单次结果上限 256 KiB 时不能读取。D2B1 为已登记的状态目标增加显式分段读取，供后续领域适配使用；D2B、D2 和 D 尚未完成。按实施前登记的 C-09R/调整O，后续依次处理大状态写入及事务、图谱和后台领域适配，D2C 及后续顺序不变。

`状态.打开后端(...)` 返回的后端新增 `await 读取分段快照()`，返回 `{版本, 数据}`。不存在的状态返回版本 0 和 null；已有状态按 24 KiB 字节片段读取，逐片检查同一版本、总长度、位置和 SHA-256，最终验证 UTF-8 和纯数据后返回。总数据上限为 8 MiB；超限、损坏、能力失效或读取中状态变更时明确报错，不拼接不同版本，也不补空或回落 JSON。每次片段读取都在 Worker 重新读取并核验当前状态；本轮未证明大文件的实际性能，后续仍需资源测试和优化。

原 `读取快照()`、64 KiB 输入及 256 KiB 单次结果限制保持原行为；新接口使用已登记目标和现有 Worker 能力，不开放任意文件/SQL。分段读取为只读，不产生写入回执；关闭能力或 Worker 后不自动恢复读取。大状态写入、跨文档原子提交及其 unknown 恢复仍待 D2B2，不能把读取成功称为完整迁移。

自动验收：在生产源码目录运行 `node tools/测SQLite状态分段读取.cjs`，4/4 通过。测试用超过旧限制的虚构多字节内容核对完整读回及原接口拒绝；在片段之间修改版本后验证拒绝拼接；验证伪造/关闭能力及非法偏移被拒绝，读取不新增回执。并重跑 D2A 21、D1 18、S16C 27、S15D 37、旧状态接入 33、备份回退 45，加本步 4 共 **185/185**。四个变更 CJS 语法和 Git 差异检查通过。

没有 UI 或外设变化，无需用户人工判断观感。测试使用隔离虚构数据，未读取正式正文、凭据或真实冻结包，未改核心调用、切换正式存储、调用模型、安装依赖、重启正式程序、上传或部署。测试仅回收自身新建并核对路径的临时目录。
