# C-14 渠道会话与内部对话映射

日期：2026-10-25。实现：`脑/渠道会话映射.cjs`；验证：`tools/测渠道会话映射.cjs`。

本步解决“本次渠道消息属于哪段内部对话”。仅使用C-13权限守卫、fake适配器和假历史处理函数；持久化验证只写脚本创建的系统临时目录。没有导入正式配置/记忆模块、创建正式聊天、调用模型或接入真实账号。

## 1. 地址与编号

唯一地址沿用C-11的JSON元组：`[渠道, 机器人账号, 会话类型, 会话编号, 发送者编号]`。不能按昵称、正文、当前桌面对话或仅发送者编号合并；字符串编号保留前导零。端点或会话任一维度不同就单独分配。

内部编号由受信服务生成，默认`channel-<randomUUID>`，在本映射表内唯一，不能由模型、消息或客户端指定。不接受路径或桌面当前编号；发生碰撞最多重新生成五次，仍失败就拒绝，不把两个地址指向同一内部编号。默认容量4096条，达到上限时只允许复用已有映射。

已有映射稳定复用。撤权保留数据但立即禁止访问；只有管理端显式重新批准、取得新许可后才可再次使用。这里没有跨渠道自动合并、人工换绑内部编号或删除历史的功能。

## 2. 先查许可，再读存档

调用顺序：fake/未来受信适配器 → C-13权限守卫 → C-14验证原许可 → 查询/分配内部编号 → 显式注入的处理函数。

C-13兼容新增`核对接收许可`，核对当前绑定、策略实例、消息编号、完整来源地址及许可时效；不会重新签发许可。映射不能通过重跑`审查接收`给任意自报身份补发许可。无许可、复制/伪造许可、来源变化、过期、时钟倒退、撤权或关闭均拒绝。

这一检查早于文件读取和目录创建；未授权消息不能探测某个映射是否存在，也不能探测存档是否损坏。群聊、陌生人仍由C-13拒绝。权限令牌只留在受信进程，不能进模型提示、渠道、客户端、日志或存档。

## 3. 接口

`创建渠道会话映射({权限, 文件=null, 生成编号, 最大记录数=4096})`：

| 接口 | 行为 |
|---|---|
| 解析接收(消息, {回复许可}) | 已批准地址不存在时分配，存在时复用；返回好、存在、内部对话编号和新建 |
| 查询接收(消息, {回复许可}) | 只查不建；无记录返回好=true、存在=false、内部对话编号=null |
| 取状态() | 仅返回已关闭、持久化，不公开身份清单或正文 |
| 关闭() | 幂等停止查询/分配，清空内存；保留显式存档供新实例恢复 |

`文件=null`时仅内存；需要跨进程恢复时必须显式传入受信配置的绝对`.json`路径，不根据渠道字段拼路径，也没有正式数据默认路径。`生成编号`和容量参数仅供受信服务配置，不能暴露为聊天参数。

`创建渠道会话路由({守卫,映射})`提供`订阅接收(处理)`和`关闭()`。处理函数收到消息及冻结的`{内部对话编号,回复许可}`，每次回调捕获自己的编号，不能依赖共享的“当前对话”变量。退订幂等，关闭只释放本路由订阅，不关闭共享守卫、策略、映射或适配器。

处理函数仍是受信内部代码；编号与许可不能直接序列化成模型上下文。发送回复继续走C-13守卫，并使用原消息的端点、会话、发送者及回复许可；得到内部编号不授予额外外发权。

存储失败不调用处理函数，由fake的接收报告明确标为处理失败。它不会静默回落到桌面当前会话或创建空历史冒充恢复成功。

## 4. 映射存档与恢复

结构为`{版本:1,记录:[{端点,会话,发送者编号,内部对话编号}]}`。仅保存地址与内部编号，不存正文、附件、消息编号、历史、凭据、令牌或private日记。地址仍属于敏感元数据；后续配置位置必须留在受保护的数据目录，不能放公共静态目录或作为普通日志/源码上传。

读取校验完整结构、版本、C-11地址、private类型、内部编号、容量和两种唯一性；超8MiB、损坏、空文件、未知版本、重复地址或重复内部编号均拒绝并保留原文。已经见过存档的实例发现文件消失时拒绝，不当空表重建。首次启动、从未见过文件时才可建立新表；若存档丢失且启动全新进程，模块没有其他来源恢复旧编号，仍需后续备份/恢复方案。

新增记录流程：独占创建`.lock` → 锁内重读已提交表 → 查重/分配 → 自己的临时文件写入并fsync → 原子替换 → 清理自己的锁。新分配遇锁直接报STORE_BUSY，不等待、不重试、不删除别人的锁；已提交映射可在有锁时只读。两个实例交错写入不会用旧快照覆盖对方记录。

写入失败保留旧档，清理自己成功创建的临时文件与锁。进程被强杀可能留下锁或临时文件；本步不自动判断过期锁或接管写入，恢复时须确认原写进程已结束，后续运维/恢复步骤再提供管理操作。文件fsync和原子替换不是对断电、存储设备损坏或所有文件系统的绝对保证。

失败只返回固定代码：INVALID_CONTRACT、FORBIDDEN、MAP_CLOSED、STORE_CORRUPT、STORE_UNAVAILABLE、STORE_BUSY、STORE_WRITE_FAILED、ID_CONFLICT、MAP_FULL；不回显原始路径、正文或异常。

这是C-14独立映射元数据的隔离持久化，不迁移现有JSON记忆，也不代替S-13的整体存储选择或C-15的消息任务队列。

## 5. 已验证与后续接线要求

34项专项验证同地址复用、各地址维度隔离、换本人编号、前导零、许可边界、撤权/重新批准、快照隔离、新实例及新Node进程恢复、交错写入、损坏存档/锁/写失败/丢失/容量/碰撞，以及假核心并发处理和原来源回复。测试中的两条批准身份全部虚构，用来验证隔离，不表示开放真实陌生人。

并行测试让第二段先完成，确认各自假历史只含自己的正文和回复，回复许可不能换目标。仅证明本地路由契约与假处理器行为；真实核心尚未接入。

后续S-12必须按映射编号显式读写历史、临时状态及长期记忆来源，不调用会切换全局当前对话的旧入口；接入时再验证真实核心的并发行为。现有长期记忆仍是本人共享的单人格资料，本步没有把它改成多用户隔离库，也不宣称正式记忆已完成多租户安全隔离。若将来开放其他人，须先设计并验证独立记忆权限与数据域。

C-15继续实现接收重放去重、发送任务状态、速率限制、断线恢复和脱敏日志。本步相同消息重放会再次交给处理函数，只保证仍使用相同内部对话编号，不能宣称已实现只回复一次。所有真实平台身份认证、核心接线、账号和服务器操作仍按步骤账本后续单步推进。
