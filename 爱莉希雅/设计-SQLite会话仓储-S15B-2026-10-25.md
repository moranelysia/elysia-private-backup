# S-15B：隔离SQLite会话/消息仓储

2026-10-25。基线`79cf068`。本轮在S-15A之后补真正的会话读写接口，只使用内存和虚构数据；正式JSON/JSONL、Electron、无界面核心、人格、模型链及记忆策略均未接线或替换。

## 与A及后续步骤的关系

A的`sqlite-fixture.cjs`保留原文档案与只读投影，用于字节核对。B的`sqlite-context.cjs`和`sqlite-chat.cjs`提供可变仓储与事务，共享一个受控连接。两者用途不同，当前没有互相导入或两份正式权威；A的档案不能冒充B新增消息的回退。E才合并测试接线、版本化迁移和新增数据逆向导出，F再做受控正式快照影子演练，S-23才切换权威。

上下文是WeakMap登记的能力，只可由`创建内存上下文({用途:'synthetic-sqlite-repository'})`创建；拒绝路径选项、伪造能力及Electron进程。原生连接/事务辅助函数只在内部模块导出，供仓储与隔离测试使用，不是IPC或用户权限系统，禁止直接向renderer、聊天或渠道开放。未来C/D可在同一上下文增加仓储，同一业务工作单元应组合内部SQL，不能相互嵌套会自行开事务的公开方法。

## 表与完整性

| 表 | 主要内容与约束 |
|---|---|
| repository_meta | 当前chat_schema版本1；已有版本或表不符时拒绝，不自动清空/补空表 |
| chat_sessions | 稳定对话编号唯一、标题/模型/模式/长期记忆开关、创建时间、扩展JSON、元数据版本、消息数/末序号/最后时间 |
| chat_turns | `(对话,轮次)`主键，规范请求指纹、两条消息编号、起序与完整保存回执 |
| chat_messages | 新消息UUID主键，`(对话,序号)`及`(对话,轮次,角色)`唯一；外键指向会话与轮次；保存正文、三类时间和JSON投影 |

SQLite内部还会建立自增序列表及唯一索引，不当作新增业务能力。开启foreign_keys、trusted_schema=OFF和temp_store=MEMORY；不安装驱动依赖或创建磁盘库。

所有读写都要求显式对话，没有全局“当前对话”、默认会话或按正文猜归属。新轮次必须先登记会话；A中的旧缺失编号/时间、分隔记录和扩展仍原样归档，本步不自动修复旧数据。新消息的UUID是新写入身份，不假称旧来源本来有此编号。

## 接口与语义

| 接口 | 语义 |
|---|---|
| 登记对话(编号,选项) | 建于必传规范UTC；模型/标题默认空、模式默认chat、Node长期开关默认false。已有编号登记幂等，不覆盖原设置或创建时间 |
| 更新对话(编号,选项) | 必须给预期元数据版本；只改显式字段。冲突拒绝，未知扩展在未显式替换时保留；消息计数变化不挤占设置版本 |
| 读取对话(编号) | 返回独立元数据副本；不存在返回null，不冒充已有空会话 |
| 列对话({上限}) | 默认100/最多200，返回还有标志；新记录建于均为规范UTC，按建于倒序，同时间以登记序稳定排序 |
| 存对话一轮(输入) | 必须含对话、稳定轮次、双正文、接收于/完成于；发生于可缺失/null。整个轮次仅一次原子提交 |
| 读最近聊天(最多,{对话}) | 默认20、上限400，按本会话写入序旧到新；不提供0代表无界全读 |
| 读消息页({对话,大小,游标}) | 默认50/上限200；初页取最新段，翻页取更早段，每页内部旧到新；附下一页游标或null |
| 取统计()/核验() | 统计只含计数；核验schema、quick_check、外键、会话计数/连续序号、每轮双消息、payload/指纹/回执一致性 |

新写入时间沿用现有独立核心的UTC严格契约，不接受本地时间并擅自猜时区。用户显示时间为发生于或接收于，分别保留发生于和接收于；回复用完成于。历史顺序依写入序号，不因迟到事件或时钟差把旧轮次插到前面；原始事件时间仍可供以后时间线使用。旧格式转换留E/F，B不批量改历史时间。

元数据及正文有大小/结构限制，不强转编号/布尔/日期，不静默去掉扩展内的undefined、getter、函数或稀疏项。读取返回白名单和副本；完整业务导出、附件和其他历史角色不在当前接口中，E接线时须保留原有全量导出与UI行为，不把200条列表当全部数据。

## 事务与回执

一轮的回执、用户行、回复行和会话计数在同一个BEGIN IMMEDIATE/COMMIT中写入；只在COMMIT正常返回后对调用方报saved。这里的saved仅表示内存事务已提交，**不代表关机后可恢复或完成正式迁移**。

同会话同轮次的规范请求再次提交时，核对摘要及实际双消息后返回相同编号/回执，不重复追加；正文或来源时间不同报冲突，不覆盖旧轮次。调用方须保留原轮次编号和原请求，不能用新的完成时间冒充同一请求。不同会话可使用相同轮次字符串，命名空间不串线。

普通SQL失败成功回滚，返回rolled-back；参数/版本/冲突拒绝返回rejected。提交结果不确定，或ROLLBACK本身失败，则返回unknown并将整条能力标为不可用，禁止继续读写/盲目重做。没有把模型调用或渠道外发放进数据库事务，也不声称能撤销已发消息。驱动/磁盘崩溃恢复仍在S-16。

## 分页与性能边界

消息按`(conversation_id,sequence)`索引做键集分页，不扫描全项目JSONL、不用OFFSET。首个窗口固定上界，后续新消息不会混入这个旧窗口。游标由本上下文HMAC签名，绑定数据库、对话、上界和当前位置，篡改、越界或跨库/跨会话使用均拒绝。同一能力的多个仓储句柄可续页，能力关闭后失效。

游标是进程内分页机制，不是访问授权。这里的“窗口”只保证B的追加型消息不受后续追加干扰；尚无编辑/删除接口，不声称跨修改快照、跨重启游标或跨机器同步。异步交错测试是在同一个Node/SQLite连接上串行执行事务，不冒充多进程并发、磁盘压力或生产性能测量。

## 附带修正与验证边界

B边界测试发现JS正则的末尾锚点可以接受末尾换行，改为完整匹配并拒绝这类编号；同样收紧A来源名称、扩展数组索引并补回归。该修正仅涉及未接线的候选库/测试，没有新增能力或步骤重排。

38项B专项及28项A回归，合计66项；包括真实SQLite约束/触发器故障、提交后驱动异常、回滚异常、游标篡改、交错写入与独立子进程依赖阻断。原生SQL故障只注入测试上下文，不添加公开故障参数。子进程阻断文件API、网络与业务模块后可完成回环；模块加载本身仍会读取自己的源码，不把它说成系统零文件读取。

内置驱动仍是同步且处于release candidate，只在独立Node测试进程使用；正式驱动、执行线程、磁盘/WAL和Linux另验。依据[Node固定版本文档](https://nodejs.org/download/release/v26.8.2/docs/api/sqlite.html)与[SQLite事务文档](https://www.sqlite.org/lang_transaction.html)，不嵌套BEGIN、不在事务内等待模型，不把内存回滚证明当断电证明。
