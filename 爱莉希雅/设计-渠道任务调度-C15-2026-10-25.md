# C-15 去重、控频、断线恢复与脱敏日志

日期：2026-10-25。实现：`脑/渠道任务调度.cjs`。专项：`tools/测渠道任务调度.cjs`；崩溃断点：`tools/fixtures/渠道调度崩溃.cjs`。

本步只组合C-11契约、C-13守卫与C-14映射，在fake渠道和独立临时目录运行。没有生产调用方、正式记忆/配置依赖、真实模型或账号；既有模块的收发行为没有改变。

## 1. 唯一处理入口

受信适配器 → C-13身份/来源许可审查 → C-14映射 → C-15持久登记 → 显式注入的处理函数 → 草稿校验 → 待发任务 → C-13发送守卫。

消息来源必须先通过权限检查；正文自称本人不授予权限。去重键为C-11完整地址加消息编号的SHA-256摘要，原始正文不写入去重记录。同正文但新消息编号仍是新输入；不同渠道、账号、会话和发送者不会因为消息编号相同而混为一条。

输入指纹按固定字段顺序包含原发生时间、回复关联、正文和附件元数据，不包含每次重放都会变化的接收时间。重排对象字段不改变语义；同来源编号偷换内容或内部对话编号时记录冲突，不覆盖原回复。冲突若发生在queued阶段，任务转blocked。

先持久化processing，再串行调用处理函数；并发重放看到已登记记录就不再次执行。处理函数收到独立消息副本和冻结的`{内部对话编号,中止}`，不拿到回复许可。成功草稿只允许`{可见性:'shared',正文,附件}`三个普通数据字段，随后再经C-11校验；访问器、额外字段、private和非法附件不能进入待发任务。

同一守卫对象最多挂一个运行调度，重复启动同一实例幂等；持久文件在实例生命周期内独占单写。S-12接线时只挂这个处理入口，不同时挂C-14示例的核心回调或绕过调度的自动回复。多个独立守卫/进程也必须由S-16保证一个端点一个正式写入实例，不能通过配置不同存档规避单写要求。

## 2. 接口与默认参数

`创建渠道任务调度({守卫,权限,映射,处理,文件=null,取现在,最小间隔毫秒=1000,重试延迟毫秒=2000,最大尝试=3,任务有效毫秒=600000,最大记录数=4096})`。

| 接口 | 行为 |
|---|---|
| 启动() | 订阅守卫接收；幂等，不调用真实模型或启用其他入口 |
| 推进() | 执行当前已授权、到期可运行的发送任务；并发调用合并到同一个串行循环，返回好和本轮尝试发送数 |
| 取状态() | 关闭/故障/持久化标志、总任务与各状态计数 |
| 取任务状态() | 任务随机编号、状态、尝试数、固定代码与下次尝试时间的副本 |
| 取日志() | 最近100条脱敏事件的独立副本 |
| 关闭() | 退订、中止、保存不确定/中断状态并释放自己的锁；不关闭共享依赖 |

文件默认null，仅内存且不承诺跨实例去重。持久化须由受信服务显式传入绝对`.json`路径；C-14映射也须配置稳定的独立存档，不能在重启时临时生成新内部编号。没有生产默认数据路径，也不从消息中取路径。

本模块不创建后台定时器。接收完成会调用推进；本地重连测试由测试驱动调用推进。后续S-16服务生命周期负责在到期/重连时显式驱动，并在退出时关闭；本步不宣称真实网络已经自动重连。

## 3. 状态与恢复

| 保存状态 | 含义及重启后的处理 |
|---|---|
| processing | 已登记、核心未得到持久化草稿；重启转interrupted，不再自动执行 |
| queued | 草稿已保存、尚待发送或明确失败后可重试；重启保留，必须等受信适配器重放原消息、重新取得许可 |
| sending | 已保存实际发送尝试；重启转unknown，不能当作未发自动重试 |
| sent | 有合法平台确认；保持终态，重放不再回复 |
| unknown | 送达结果不明、回执异常或发送中断；保持终态，不盲目重发 |
| failed/cancelled/blocked/expired/interrupted | 保留原因和去重记录，不自动重做；需要新请求或后续明确管理流程 |

发送前先保存sending、尝试次数和最近发送时间，再调用守卫。收到合法回执后才保存终态；送达成功后回执落盘失败，会停止实例，旧档仍为sending，重启保守转unknown。处理异常、非法草稿和迟到草稿也不重新调用核心。

这是本地去重与保守恢复，不能声称分布式“恰好一次”。核心执行与其未来记忆写入还不是一个事务；核心处理中断可能没有回复，且不能靠自动重跑掩盖。真实适配器也必须把不确定结果标unknown，只有确定未交付的失败才能标可重试。S-12与真实渠道验收继续验证各自边界。

## 4. 控频、顺序与权限

一个调度同一时刻只有一个发送在途，整个固定端点默认至少间隔1秒；最近尝试时刻随存档恢复，重启或时钟倒退不能重置间隔。同一内部对话按登记顺序发送，前一条仍processing/queued/sending时后一条不越过；未知结果之后的真实平台送达次序无法保证，不把本地串行描述为网络绝对有序。

仅failed且可重试的合法回执重试，默认总计最多3次，退避依次2秒、4秒，复用同一请求编号及原草稿。unknown、权限/能力不足、过期或取消不重试。降低重试上限会终止已经达到新上限的旧queued任务；降低容量不会清除合法旧记录，只禁止继续新增。默认任务期限从首次登记起10分钟，重放不续期；平台回复窗口仍由适配器按原发生时间检查。

出队前重新审查当前许可，实际发送仍经过C-13守卫。许可只保存在进程内存；存档不生成、不恢复或重新签发许可。过期许可须等待受信适配器对原来源重新审查；另一条消息不能批准旧任务。queued超过期限即停止。

合法权限配置变更清除所有内存许可，将queued标blocked，并向正在执行的核心传播AbortSignal；C-13同时中止尚未交付的发送。生成后再核对原许可，迟到草稿不保存。重新添加本人也不自动恢复blocked任务。权限配置本身仍由受信管理入口负责，C-15不是身份管理持久化服务。

关闭时processing转interrupted、sending转unknown，queued保留但失去内存许可；迟到处理/发送结果不能再写盘，避免覆盖后来启动的实例。中止只代表本地传播信号，不等于撤回平台已交付消息，处理函数也须主动支持中止。

## 5. 存档、日志与日记来源

版本1存档包含固定端点、最近发送时间、去重/任务记录与最近100条事件。任务保留来源元数据、输入摘要、内部编号、状态、shared发送载荷和合法回执；不保存原始接收正文、回复许可、模型提示或原始异常。SHA-256摘要不是加密或匿名化，来源元数据及shared发送正文仍属于私有任务数据，不能当成公开日志、普通导出或源码上传。

日志严格只有`于、事件、任务、代码、尝试`，任务编号由服务随机生成；不含来源账号/联系人、消息正文、内部对话编号、原始去重键、令牌或异常。管理状态也不暴露这些内容。

private草稿在形成发送对象前拒绝。日记来源必须先通过既有`日记外发闸门.cjs`的shared投影；shared标签不能给任意正文授权，本模块不能从普通字符串推断其是否来自private日记。S-12必须继续保证private不进模型上下文，也不能由调用方把私密正文改贴shared标签。专项在配置指向隔离目录的子进程里验证混合日记投影，private片段未进入发送与重试存档。

默认最多4096条记录和64MiB文件；不因日志裁剪或时间推移自动删除去重记录。容量/存储满时拒绝新增或停止写入，保留旧档；留存、归档和备份策略在后续服务运行步骤确定，不用静默淘汰已处理记录换取继续发送。

存档版本、字段、来源、请求归属、状态组合、回执和唯一性均校验。损坏、空文件、未来版本、重复记录和private发送对象都拒绝且保留原文。写入为自己的临时文件 → fsync → 原子替换；失败停止实例，清理自己成功创建的临时文件，不覆盖旧档。运行中已见文件消失也停止，不重建空表。

实例持有`.lock`直到关闭，遇锁直接拒绝，不自动判断陈旧或删除他人的锁。进程异常退出后只有确认原写进程确已结束，才可由后续受信运维流程处理残锁；测试用execFileSync确认专用子进程已结束后清理其隔离锁，再测试恢复。原子替换与fsync不是对断电或设备故障的绝对保证，仍需要S-16/S-24备份恢复验收。
