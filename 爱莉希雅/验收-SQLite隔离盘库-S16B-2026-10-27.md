# S-16B 隔离磁盘库验收

日期：2026-10-27。源码基线 `faedc0a`，实现提交见共同协作本步记录。本轮只做B；按用户已选A为后续Worker提供盘库能力，尚未创建Worker或接入正式核心。

## 实现及版本边界

- 新增 [sqlite-disk.cjs](storage/sqlite-disk.cjs)，只在真实系统临时目录的直属新建 `elysia-sqlite-disk-*` 子目录保存；不接受任意新建目录参数，打开也必须有匹配的专用标记。生产目录、路径重定向、链接/硬链接、额外文件、用途或私密声明不符均拒绝。不是可直接部署的正式存储入口。
- 用途分为 `synthetic-sqlite-disk` 和须显式 `包含私密:true` 的 `isolated-local-sqlite-disk`；后者保持原本机迁移/回退用途，不将本机v5包伪装synthetic。本轮两类都只使用虚构材料，没有读取真实冻结包、正式正文或凭据。
- 新建先在隔离内存仓校验/初始化，序列化后只写全新文件；数据库及标记写出/fsync、读回哈希后才发布ready标记。发布前失败不就绪，rename已生效但回执丢失明确报 `SQLITE_DISK_PUBLICATION_UNKNOWN` 并附自建目录，不能盲目重做或称未落地。采用的[Node serialize接口](https://nodejs.org/download/release/v26.8.2/docs/api/sqlite.html#databaseserializedbname)依赖当前已核运行时，不新增驱动依赖。
- 盘库 `application_id=0x454c5953`、`user_version=2`，原业务仍20表；`repository_meta` 新增三项 `disk_storage_format`、`disk_metadata`、`disk_metadata_sha256`。元数据内部版本1，保存当前原文基线、资源映射和外部文件的路径/大小/哈希，附件二进制不塞入SQL。
- 物理盘格式和逻辑候选包版本分开：导出快照排除上述物理保全键，原v2/v3/v4/v5、架构和用途校验保持；内存恢复器拒绝注入盘库私有键，不能降级绕过。物理版本未知、缺库、坏库、缺表/登记、额外表、元数据哈希或语义不符，先由只读连接拒绝，不自动补表/建空或回落JSON。[Node只读选项](https://nodejs.org/download/release/v26.8.2/docs/api/sqlite.html#new-databasesyncpath-options)
- 原文基线/引用与业务同事务保存；提交失败还原SQL和闭包元数据，提交结果不确定封闭旧能力。private删除时保存当前投影，新增持久基线不留被删正文；删除档案只留标记。不声称旧磁盘页或历史备份物理擦除。
- 正常连接实际读回 WAL、FULL、外键ON、trusted_schema OFF、busy_timeout=250ms，禁扩展。基础锁使用独占新建，仅释放自身令牌；第二连接/残锁拒绝，关库失败不放锁、停止写能力。完整所有权/残锁接管和Worker背压留C，当前锁不是C已完成。

这些是 C-09N 对B的版本/元数据/失败处理细化，顺序仍B→C→D→E→F→G，无新增记忆业务能力。

```powershell
Set-Location -LiteralPath 'F:\elysia\爱莉希雅'
node 'tools/测SQLite隔离盘库.cjs'
```

通过标准：结尾 `SQLite S-16B: 30/30`、进程退出码0，无FAIL；测试自行建立临时盘库，由独立进程重开并清理。它不需要退出/启动正式程序、模型密钥或真实聊天，也不向正式目录写数据。

复核接口示意（创建的盘库仍仅临时隔离用途；手动示意不自动删除其目录）：

```javascript
const { 新建隔离盘库, 打开隔离盘库 } = require('./storage/sqlite-disk.cjs')
const a = 新建隔离盘库({ 用途: 'synthetic-sqlite-disk' })
const 目录 = a.目录
a.关闭()
const b = 打开隔离盘库({ 用途: 'synthetic-sqlite-disk', 目录 })
b.仓储.核验()
b.关闭()
```
