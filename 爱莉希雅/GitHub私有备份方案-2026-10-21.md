## 为什么不把原始记忆放进私有仓库

Private 只代表仓库不公开，不等于端到端加密保险箱。账号误授权、令牌泄漏或以后误改可见性仍可能
暴露聊天与个人资料。源码仓应保持可共享、可审计；若以后需要异地备份记忆，建议另做 AES 加密归档，
只上传密文，并与源码仓分开管理。

## 实施步骤（等待用户确认后执行）

1. 在 `F:\elysia` 创建严格白名单式 `.gitignore` 和 `.gitattributes`；不移动、不删除现有文件。
2. 创建脱敏的 `elysia.config.example.json`，真实配置继续留在本机。
3. `git init` 后只暂存预定集合，检查 Git 状态、总大小、超过 50/100MB 的文件和 LFS 跟踪情况。
4. 对暂存区做二次密钥与私人路径扫描；任何命中先停止，不提交。
5. 创建 GitHub Private 空仓库 `elysia-private-backup`。由于插件没有建仓入口，可由用户在网页创建，
   或在用户确认后由 Agent 操作已登录的 GitHub 页面创建。
6. 初始提交后添加远端并推送；随后从 GitHub 重新读取仓库可见性，确认确实为 Private。
7. 增加一个安全的一键备份入口：先展示变更摘要和待提交文件，再要求提交说明，最后 commit + push；
   不自动提交密钥、记忆或新出现的大文件。

## 验收标准

- GitHub 仓库明确显示 Private。
- `git status` 干净，LFS 文件可列出，单个普通 Git 对象不超过 GitHub 100MB 限制。
- 从空目录克隆后，执行 `npm install` 能恢复依赖，正式源代码和 v13 运行模型齐全。
- 仓库搜索不到真实 API Key、聊天记录、事实、经历、小本子、本机绝对路径或私人附件。
- 原工作区没有文件被移动或删除，正式 Electron 程序仍能从 `F:\elysia\start-all.cmd` 启动。
