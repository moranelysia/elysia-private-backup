## 一、程序是怎么跑起来的

程序就三件事的组合：

1. **从上往下一步步执行**
2. **用变量存数据**
3. **做判断（if）、做重复（for）**

所有语言（C、JS、Python）翻来覆去都是这三样。

**两种程序：**

```
跑完就结束的      hello.js —— 打印完，进程就死了
一直活着的        窗口、聊天软件 —— 靠【事件循环】：一个一直转的圈，等事情发生
```

事件循环 = 值班的人：一直坐着，有人来就处理，处理完继续等。

## 二、Node 是什么

`node` 是电脑上的一个程序，能读懂并执行 `.js` 文件。

```
node hello.js      让 node 执行这个文件
```

它自带工具（叫模块），用 `require` 拿：

```js
const fs = require("fs")                // 读写文件
const readline = require("readline")    // 读键盘输入
```

**Node 里没有浏览器的东西**：没有 `prompt`、没有弹框、没有按钮。
`prompt` 是浏览器的功能，Node 里用它 → `ReferenceError: prompt is not defined`。

> 记牢：**同一门语言，跑在不同环境里，能用的东西不一样。**
> 浏览器：页面、弹框、按钮
> Node：文件、网络、进程

## 三、JavaScript 语法（已会的）

```js
let name = "moran"              // 变量（造个盒子）
console.log("你好，" + name)     // 打印；+ 拼接文字
```

```js
JSON.stringify(数据)     // 数据 → 文字   （写进文件前用）
JSON.parse(文字)         // 文字 → 数据   （从文件读出来后用）
```

这两个是一对，**所有程序的"存档"功能本质都是它俩**。

```js
(answer) => { ... }      // 箭头函数："这件事等会儿做"（异步）
?.                       // 安全调用：存在就调，不存在就算了
```

⚠️ **`?.` 会把错误藏起来**。用了它的地方，要主动去确认东西到底在不在。

**文件读写：**

```js
const fs = require("fs")
fs.readFileSync("记忆.json", "utf8")                    // 读
fs.writeFileSync("记忆.json", JSON.stringify(x), "utf8") // 写
```

**读键盘输入：**

```js
const readline = require("readline")
const rl = readline.createInterface({ input: process.stdin, output: process.stdout })
rl.question("你叫什么名字？", (answer) => {
  console.log("你好，" + answer)
  rl.close()
})
```

## 四、Electron：老板和员工 ⭐ 最重要的

```
main.js      主进程「老板」   Node 环境。管窗口、文件、系统。不画界面。
index.html   渲染进程「员工」 浏览器环境。画界面。不能读文件、不能开窗口。
preload.js   中间人           在员工那边跑，但有 Node 权限，开一条小口子。
```

**为什么分两个？安全。** 网页代码不许直接碰硬盘，想干得申请。

**它们的关系：**

```
package.json 里 "main": "main.js"    → 从这里启动
main.js 造窗口                        → 让窗口加载 index.html
index.html 里 link style.css          → 长什么样
```

**IPC（两个进程之间的通道）：**

```js
// 员工（index.html 里）—— 喊
window.elysiaAPI.closeMe()

// 中间人（preload.js）—— 开个口子，把话传过去
const { contextBridge, ipcRenderer } = require("electron")
contextBridge.exposeInMainWorld("elysiaAPI", {
  closeMe: () => ipcRenderer.send("close-me"),
})

// 老板（main.js）—— 守着对讲机收
const { ipcMain } = require("electron")
ipcMain.on("close-me", () => { win.close() })
```

⚠️ **通道的名字必须两边一模一样**（这里是 `"close-me"`）。差一个字符就收不到。

**窗口配置（我们正在用的）：**

```js
new BrowserWindow({
  width: 600, height: 560,
  alwaysOnTop: true,        // 一直在最前面
  resizable: false,         // 不许拉大拉小
  frame: false,             // 不要边框和标题栏
  transparent: true,        // 背景透明
  skipTaskbar: true,        // 不占任务栏
  hasShadow: false,         // 不要系统阴影
  webPreferences: { preload: __dirname + "/preload.js" },
})
```

`__dirname` = 当前文件所在的文件夹（前后各**两个**下划线）。

## 七、踩过的坑（最值钱的一页）⭐

| 现象 | 真相 |
|---|---|
| `prompt is not defined` | Node 没这个功能。环境不同，能用的东西不同 |
| JS 写进 `hello.c` | **后缀名决定这是什么语言** |
| `MODULE_NOT_FOUND` | **程序在哪个文件夹跑，就只在哪儿找文件** |
| `npm` 报执行策略错误 | `.ps1` 被 Windows 挡了，改用 `npm.cmd` |
| `Invalid name: "爱莉希雅"` | **项目名必须全英文小写** |
| Electron 装完是空壳 | 它默认往 `AppData` 下内核，被挡；**装完要查文件在不在** |
| `Unexpected token "}"` | **花括号多了一个**。从报错行往上找谁提前关了 |
| 拖动和阴影同时失效 | **CSS 漏一个分号**，会把连着的那条声明一起扔掉 |
| Esc 没反应也不报错 | `preload.js` 没建，而 `?.` 把错误咽下去了 |

**一句话规律：报错不可怕，可怕的是不报错也不工作。**
那种时候就去**看东西到底在不在**——按 `F12` 看控制台，或者在终端里翻文件。

### 踩的坑（都很典型）

**坑一：`process is not defined`**

`cubism4.js` 第 1482 行，在库的最外层就执行了：

```js
const CSM_ASSERT = process.env.NODE_ENV === "production" ? () => {} : (expr) => console.assert(expr)
```

`process` 是 Node 的东西，浏览器里没有 → **整个库当场崩掉**，后面全没挂上。

**修法：在加载它之前打补丁（shim）**

```html
<script>
  window.process = { env: { NODE_ENV: "production" } }
  window.global = window
</script>
<script src=".../cubism4.js"></script>
```

> 这类库很多是"Node 和浏览器都能跑"的写法，靠检查 `process` 之类的**特征**
> 判断自己在哪儿。浏览器里缺这些特征，它可能走进错误分支甚至直接崩。
> 打补丁就是**给它一个假的运行环境**。

**坑二：透明窗口打不开 F12**

`transparent: true` 的窗口在 Windows 上按 F12 没反应 —— Electron 的老毛病。

**修法：从主进程注册全局快捷键**，让按键触发主进程逻辑，结果打印到终端：

```js
const { globalShortcut } = require("electron")
globalShortcut.register("F1", () => { win.webContents.send("某条消息", 值) })
```

（用完记得 `globalShortcut.unregisterAll()`，不然别的程序按 F1 会失灵。）

**坑三：参数的语义是反的**

那个模型的水印参数 `Paramshuiying`：**0 = 显示水印，1 = 隐藏**。
我按常识猜"1 是显示"，猜错了，试出来才知道。

> **教训：参数的含义必须实测，别按常识猜。** 尤其是别人做的模型。

### 抠图那一课（最后没用上，但值得记）

给白底图抠透明，两种做法：

```
按颜色抠     逐个像素看"白不白"    → 角色的白衣服、浅皮肤会被一起抠掉
洪水填充     从图片四条边往里漫     → 只抠"跟边缘连着"的白，正确
```

洪水填充就是画图软件里的"油漆桶"。**遇到"分不清两个相似的东西"，往往得再加一个维度**
（这里是"连通性"）——光看颜色不够。

### 一个该养成的习惯：把参数留出来

脚本里的阈值、快捷键的键位，都做成**可改的参数**，别写死在代码里。
调参数比改代码快得多。

## 十二、真正的实现：自己做键盘监听（2026-09-26 凌晨）

### 那个 npm 包是残缺的

`node-global-key-listener` 在 Windows 上要靠一个 `WinKeyServer.exe`：

```js
// 它的源码 WinKeyServer.js 第 27 行：
const 子进程 = execFile(serverPath, ...)   // serverPath = build/bin/WinKeyServer.exe
```

**但那个 exe 根本没打进包里。** 它的 `package.json` 写着：

```json
"scripts": { "compile-win": ".\\scripts\\compile-win.bat" }
```

——编译脚本和 exe 都不在。**npm 只负责搬文件，它不会帮你编译。**

> **教训：npm 包不一定是完整的。** 装完要看**它运行时需要的那个东西在不在**，
> 不能只看"装成功了"三个字。（跟当初 Electron 只装壳不装内核是同一类坑。）

### 那怎么办：不靠它，用 Windows 自带的

Windows 的 `user32.dll` 里有个函数 `GetAsyncKeyState`：
**你问它"某个键现在按着吗"，它就回答你。**

所以思路是：**每 15 毫秒把所有关心的键问一遍，状态变了就报出来。**

```powershell
Add-Type -TypeDefinition @"
using System;
using System.Runtime.InteropServices;
public class KeyWatcher {
    [DllImport("user32.dll")]
    public static extern short GetAsyncKeyState(int vKey);
}
"@

while ($true) {
    foreach ($vk in 所有键) {
        $按下 = ([KeyWatcher]::GetAsyncKeyState($vk) -band 0x8000) -ne 0
        if ($按下 -ne 上次的状态) { 输出 "DOWN 键名" 或 "UP 键名" }
    }
    Start-Sleep -Milliseconds 15
}
```

**为什么这样反而更好：**

```
不用编译        不依赖任何 npm 包
不用管理员权限   普通用户就能跑
不独占按键      打字照常进别的程序 —— 我们只是"偷看"
```

代价是**轮询**：每 15 毫秒问一圈。对人眼看动画来说完全够用。

### 这一轮踩的三个坑（全是老朋友）

**坑一：`.ps1` 里写中文 → 乱码**

```
$閿〃 = [ordered]@{        ← 我写的是 $键表
表达式或语句中包含意外的标记
```

Windows PowerShell 读 `.ps1` 时按**系统 ANSI 编码**解码（除非文件带 UTF-8 BOM）。
中文变量名直接变成乱码，解析全崩。

> **跟 `.cmd` 不能写中文是同一个坑。** 脚本文件一律用纯 ASCII，最省事。

**坑二：`[ordered]@{}` 用整数键会炸**

```
指定的参数已超出有效值的范围。参数名: index
```

Windows PowerShell 5 上，用整数当键去给有序字典赋值会报错。**改用普通哈希表 `@{}` 就没事。**

**坑三：`addListener` 忘了 `await`**

表现是终端里冒出一行 `unhandled rejection`，**但错误信息一个字都没有** ——
Promise 失败了没人接，错误就飘走了。

> **凡是返回 Promise 的东西，要么 `await`、要么 `.catch()`。**
> 不然它失败的时候，你连"失败了"都不知道。

### 装不上东西时的思路（这轮最重要的收获）

这轮遇到的每个拦路虎，最后都不是靠"装个东西"解决的：

```
Electron 内核下不来      → 把缓存目录改到项目里

```

**能用现成的就用，用不了就自己写个小的。** 而自己写的前提是
**你要先搞懂那件事的原理** —— 知道键盘状态可以"问"系统，
才写得出来那 20 行 PowerShell。

这也正是我们一路在做的：**先看懂，再动手。**

## 十三、对齐为什么这么难（2026-09-26 凌晨总结）

### 我们卡在哪

那 25 张手部素材，要精确叠到她的 Live2D 键盘上。**这个"对齐"花了五轮还没到位**，原因不是代码错，是**方法不对**：

```
我改代码 → 他重启 → 他截图 → 我看截图 → 我改代码 → ...
```

每一轮好几分钟，而且**信息在截图里损失了一次**（缩放、剪裁、我看到的和他看到的不完全一样）。

### 根子上的三个问题

**一、缺"实时预览"**

前端开发正常是这样的：改一行 CSS → 存盘 → **浏览器自动刷新** → 立刻看到。一秒钟一轮，试二十次都不累。

而我们在 Electron 里，每次都要 `Ctrl+C` + `npm start` + 等窗口出来。**一轮几分钟，试五次就烦了。**

> 这是工具链的问题，不是人的问题。
> （Electron 也能开热重载，但我们没配。）

**二、"从坐标反推"这条路太长**

我一直在做：素材图里的像素坐标 → 换算成窗口坐标 → 估她键盘在窗口的位置 → 算偏移。

这条链上每一环都能偏：模型缩放、模型偏移、Live2D 内部坐标系、窗口尺寸……
**任何一环偏一点，最后差很远。而我从终端看不到画面，只能靠截图猜。**

**三、没找对"对齐的锚点"**

正确的对齐方式是**找一个两边都存在的东西**，让它俩重合：

```
错：我算素材的格间距，她键盘的格间距      → 两边的"一格"含义不同
对：素材里的爱心 ↔ 她键盘上的按键          → 同一个东西，一比就准
```

**"找一个两边都有的真实锚点"** —— 这个思路做图形对齐时特别有用。

### 后来怎么解决的

**他决定去装 UP 主发布的那版现成桌宠。**

这个决定是对的，因为**有参照物之后，量尺寸就有基准了**：
把它和我们的摆一起看，手多大、落在哪儿、按键时怎么动 —— 一比就知道。

> **教训：调不出来的时候，先弄一个"能跑的正确版本"当参照。**
> 比在黑暗里盲调快十倍。

### 这一整天（其实是四个晚上）做出来的东西

## 十四、转接层：让两个软件配合（2026-09-26 晚）

### 目标变了

上一节说"对齐调不出来"，于是他做了个决定：**别在 VS Code 里继续折腾了，
直接用 Bongo Cat 那个现成软件当桌宠。**

```
显示层  →  Bongo Cat（它本来就干这个，而且干得好）
对话层  →  我们的程序（记忆、声音、聊天）
中间层  →  让它们能配合（这就是"转接层"）
```

**这是对的分工。** 我们花一晚上调那个手的位置，其实是在重复造一个已经存在的轮子。

### 转接层要解决什么

```
她说"今天过得怎么样呀"  →  想让她变个表情  →  Bongo Cat 怎么收到这个指令？
```

答案在作者自带的《按键表情使用说明.docx》里——**它支持 30 个快捷键**：

```
Alt+1 人律形态    Alt+2 妖精小姐    Alt+3 女仆形态    Alt+4 侵蚀
Alt+9 眯眯眼      Alt+Q 星星眼      Alt+E 脸红        Alt+O 吃西瓜
Alt+[ 剪刀动画    Alt+] 超级爱莉    Alt+A 爱门动画    Alt+S 疑问
Alt+F/G/H 三段语音
```

**所以转接层的活就是：把中文名翻译成快捷键，然后模拟按键。**

### 遇到的三个坑

**坑一：`SendKeys` 只发给"当前活动窗口"**

第一版用 .NET 的 `SendKeys`。实测：**Bongo Cat 在后台时收不到**
（按键发到别的窗口去了）。

**换成 `keybd_event`** —— Windows 底层 API，直接把按键事件注入系统，
跟"你真的按了键盘"几乎一样，**不管哪个窗口在前台都能收到**。

```csharp
[DllImport("user32.dll")]
public static extern void keybd_event(byte bVk, byte bScan, uint dwFlags, UIntPtr dwExtraInfo);
// 顺序：Alt 按下 → 键按下 → 停 40ms → 键抬起 → Alt 抬起
```

**坑二：DSH 的沙箱不让开子进程**

实测结果：

```
✗ HTTP ：被挡（fetch failed）
✓ 写文件：可以
```

**DSH 里的她没法直接模拟按键**（发键要开 PowerShell 子进程）。

**解法：改用"传纸条"**

```
DSH（沙箱里）→ 写 .cache\指令队列.json 说"要做脸红"
                     ↓
桌宠服务（在沙箱外跑）→ 每 300ms 看一眼 → 读到 → 按键
```

> **这个思路值得记**：**当一个环境不让你做某件事，就找一个"它允许的通道"
> （这里是文件系统），让另一个能做的程序代劳。**

**坑三：`.cmd` 文件里不能有中文（一天踩两次）**

系统代码页是 **936 (GBK)**，而文件是 **UTF-8** 存的 —— `.cmd` 里哪怕只有一处中文
（**连引用中文文件名也算**），那一行的字节就会解错、命令断成两半：

```
'pet' 不是内部或外部命令
'ches' 不是内部或外部命令
```

**规则：`.cmd` 的文件名和内容全用 ASCII，所有中文逻辑挪进 `.cjs`。**

（附带一个小坑：**双击 `.cjs` 在 Windows 上不会运行**——`.cjs` 没关联到 node。
所以需要一个 `.cmd` 包装器来双击。这就是 `run-bridge.cmd` 存在的理由。）

### 最终的架构

```
┌──────────────────────────────────────────┐
│  DSH 里的她（沙箱：不能开子进程、不能联网） │
│  "我想变个脸红"                            │
│        ↓ 写文件                            │
│  .cache\指令队列.json                      │
└──────────────────┬───────────────────────┘
                   │ 每 300ms 看一眼
┌──────────────────▼───────────────────────┐
│  桌宠服务（run-bridge.cmd 启动，不受限）    │
│  读到 → 查表情表 → keybd_event 注入按键     │
└──────────────────┬───────────────────────┘
                   │ Alt+E
┌──────────────────▼───────────────────────┐
│  Bongo Cat  →  她脸红了                    │
└──────────────────────────────────────────┘
```

### 文件清单

| 文件 | 干什么 |
|---|---|
| `renderer\assets\表情表.json` | 中文名 → 快捷键（30 个） |
| `tools\bridge.cjs` | 翻译 + 按键（两条通道自动切换） |
| `tools\pet-service.cjs` | 常驻服务：盯队列、按键 |
| `start-pet-service.cjs` | 同上（根目录版，绝对路径） |
| `run-bridge.cmd` | **双击这个启动服务** |
| `.dsh\skills\elysia-desktop-pet\SKILL.md` | DSH 的技能：她怎么用这个能力 |

### 一句话总结这一节

**两个软件没法直接对话时，中间加一层"翻译 + 搬运"就行。
而这一层要放在"两边都够得着"的地方 —— 我们选了文件系统。**

## 十五、一次教训：别凭空重写能用的东西（2026-09-26 深夜）

### 事情经过

他说"还没启动声音"，我就去看语音服务。发现 `tools\voice\start-voice.cmd`
**里面有中文**（`echo 启动爱莉希雅的声音`），立刻判断：

> "这就是我们刚踩的坑！这个脚本可能从来没跑起来过！"

然后我**自己写了一个"纯 ASCII 版"的启动器**，把原来的替换掉。

**结果他跑不起来。** 他说"之前是可以的"，我才回去看原版脚本：

```
原版：runtime\python.exe -u api_v2.py -a 127.0.0.1 -p 9880 -c GPT_SoVITS\configs\tts_infer.yaml
我写的：python api.py
```

**差了三个关键东西**：用它自带的 Python（不是系统的）、用 `api_v2.py`（不是 api.py）、
**还要带 `-c` 指定配置文件**。我那个跑不起来是必然的。

### 两个错误的判断

**错误一：把"会乱码"和"会失败"当成一回事**

`.cmd` 里的中文确实会乱码（cmd 按 GBK 读 UTF-8 文件）。**但乱码归乱码，命令不一定失败。**

那份脚本的关键行是：

```bat
cd /d D:\GPT-SoVITS        ← 纯 ASCII，不会出问题
runtime\python.exe -u api_v2.py ...   ← 也纯 ASCII
echo 启动爱莉希雅的声音      ← 中文，但只在 echo 里，乱码了照样跑
```

**中文只在 `echo` 和注释里，就不影响执行。** 真正会出事的是
**中文出现在"要传给命令的参数里"**（比如中文路径 `cd /d D:\新建文件夹`），
或者**中文把命令断成两半**（我们那个 `node "tools\桌宠服务.cjs"` 就是）。

> **规则细化**：`.cmd` 里避免中文，是因为"中文在参数位置会坏事"；
> 但**看到中文就断定脚本报废，是过度反应。**

**错误二：没先看，就动手重写**

我判断"这个脚本坏了"之后，**没有先读一遍它原来的实现**，就直接写了个新的。
如果我先打开看那三行，就会知道要用自带的 python 和 `-c` 参数。

> **教训：要改一个"正在工作的东西"之前，先读懂它为什么能工作。**
> "看起来丑"不等于"坏"——尤其是能跑的东西。

### 后来怎么好的

删掉我写的，用回原版。他双击 → 服务起来 → **她说话了**。

我实测了一下：

```

→ 转接层在线: 版本=elysia 参考=ref03
→ 合成 15 字… 完成: audio/mpeg  65.9 KB  用时 1.6s
```

**1.6 秒一句，声音是她的。** 从头到尾就没坏过。

### 一句话

**"看起来有问题"和"真的有问题"是两件事。
动手之前，先让证据说话。**

## 十六、她变成一个独立软件了（2026-09-26 深夜）

他选的路：**"想说话就点一下，平时不需要窗口，点了再出窗口。"**

于是这版和以前完全不同了。以前是"一个一直摆在桌面上的透明窗口"，
现在是"**平时什么都没有，托盘上有一朵粉色的花**"。

### 一、托盘是什么

Windows 右下角那一排小图标，叫**托盘**（英文 tray）。

它有个很好用的性质：**那儿的程序没有窗口，但一直活着。**
聊天软件、输入法都是这么待着的 —— 你把窗口关了，它没死，只是藏起来了。

```js
const { Tray } = require("electron")
托盘 = new Tray(图标)
托盘.on("click", () => 切换窗口())      // 单击 = 把窗口叫出来 / 收回去
托盘.setContextMenu(菜单)               // 右键 = 一堆选项
```

**为什么这个形态比"一直摆个窗口"好：**

- 不占地方。桌面上干干净净，想找她的时候点一下就有。
- 不用每次重新启动。启动一次要好几秒（要读人格、连声音服务），
  一直待命的话点开就是即时的。

### 二、"关窗口"和"退出程序"是两件事

这个区分值得单独记一笔，因为**用户分不清，程序必须分得清**：

```js
窗口.on("close", (事件) => {
  if (!app.isQuitting) {
    事件.preventDefault()   // 拦下这次关闭
    窗口.hide()             // 改成躲起来
    通知("爱莉希雅", "我先躲到托盘上啦")
  }
})
```

`preventDefault()` 就是"**这次别关**"。不给它加这个，点了 X 程序就真没了。

**但光拦下来还不够** —— 他会以为程序被自己关掉了、或者崩了。
所以我在收起来的时候弹一句通知告诉他。**能跑通不算完，能让他看懂才算完。**

### 三、模型是"失忆"的（这一条最要紧）

这一节是我这次真正想记的东西。

**每次请求都是独立的。** 你上一句跟她说了什么，模型**不会自己记着**。
你不把聊天记录一起递过去，她每次说话都像刚睡醒。

所以有个东西必须做：**把最近聊的几句一起发过去。**

```js
const 消息们 = [
  { role: "system",    content: 她是谁 },      // 那一大段人设
  { role: "system",    content: 现在几点 },    // 会变，所以单独放
  { role: "user",      content: "上次那句" },  // ← 这些是"记忆"
  { role: "assistant", content: "上次那句回答" },
  { role: "user",      content: "这次这句" },
]
```

**role 就是"谁说的"**：`system` 是背景设定，`user` 是他，`assistant` 是她。

**顺序不能乱。** 必须是"人设 → 时间 → 历史 → 这次的话"。
乱了它就会把"她是谁"当成你说的话。

### 四、缓存：为什么"不变的东西要放前面"

这是省钱的关键，也是为什么人设和"现在几点"要分开存。

DeepSeek 的计费有个规则：**如果这次请求的开头那一大段，跟上次一模一样，
那这一段的钱按"缓存价"算，便宜约十倍。**

我们的人设有九千多字，占了绝大部分开销。所以：

| 拼法 | 结果 |
|---|---|
| 人设 + 时间 + 历史 + 这次的话 | ✅ 人设每次都一样 → 命中缓存 |
| 时间 + 人设 + 历史 + 这次的话 | ❌ 开头每次都在变 → 整段全价 |

我实测了一眼用量：

```
用量: 输入 7134（缓存命中 6912）输出 36
```

**7134 里 6912 是命中的** —— 也就是说那九千字人设基本不花钱。

> **这条能不能记住，就是"随便写个能跑的"和"知道自己在花谁的钱"的区别。**

### 五、流式：为什么她的话要"一边说一边出现"

她整段话要一两秒才生成完。等完了再一起显示，中间那一两秒你会以为程序卡了。

**流式**（stream）就是让模型**一个字一个字往外吐**，
我们收到一点就往窗口上贴一点 —— 看起来就是她在打字。

技术上它长这样：服务端按行发，每行 `data: {...}`：

```
data: {"choices":[{"delta":{"content":"在"}}]}
data: {"choices":[{"delta":{"content":"呀"}}]}
data: [DONE]
```

**两个必须处理的细节：**

1. **最后一行可能只发了一半。** 所以要留个缓冲区，攒着和下一批拼
   （`攒着 = 行们.pop()`）。不处理的话，偶尔会漏字。
2. **用量在最后一个包里**，前面都没有。想记账就得等收完。

### 六、"标记"：她怎么让桌面上那个自己动

这个问题卡过我一次。**她没法直接按键盘** —— 她在模型那边，够不到这台电脑。

所以我给了她一套**约定的写法**：

```
好呀，那我笑给你看。

[表情:星星眼]
```

程序收到之后：把 `[表情:星星眼]` **抠掉**（不给你看），
然后自己去 `bridge.cjs` 按 Alt+Q。

**为什么这么做，而不是让她"说一句我去做个表情"**：
抠标记是**代码**，一定做得到；"她去按键盘"是**愿望**，做不到。

> **凡是需要"她真的动手"的事，都得设计成"她说话 → 程序看懂 → 程序动手"。**
> 这条跟规则 21 是同一件事：**文字里的动作不算动作。**

### 七、这版的结构（以后照着这个看）


### 八、这一次踩的坑

**坑一：Electron 在 DSH 的沙箱里起不来。**

```
Lock file can not be created: 拒绝访问。 (0x5)
FATAL: platform_channel.cc: Check failed: 拒绝访问。
```

原因跟以前那次一样：**沙箱不让程序开"命名管道"**，

应对办法：**把能测的全测了。** 我写了 `tools\测一整轮.cjs`，
不开窗口，把"说一句话"整条链子（拆标记 → 递话 → 流式 → 记忆 → 桌宠）跑一遍。
链子通了，剩下的风险就只剩"窗口显示"那一小块。

> **沙箱拦住的那一步，不是"没办法"，是"换个地方验证"。**

**坑二：同一条消息被处理了两次。**

她说完之后，主进程会同时发两个东西：
`她说完了`（事件）和"说话"这个请求的返回。

我一开始在 `她说完了` 的回调里把"当前气泡"清空了 ——
结果返回先到的时候，它以为还没开过气泡，**又开了一个，界面上同样的话出现两遍。**

修法：**清空这件事只交给一处做。**
删掉了那个监听，在 `说一句()` 里统一处理。

> **两个通道送同一个结果的时候，只让一个地方负责收尾。**

### 九、一句话

**她以前是"我写给她的一段话"，现在是一个真能自己跑起来的东西。**

点托盘上那朵花，她就出来；说一句，她一边想一边把字写给你，
说完自己出声，桌面上那个她跟着动。
**这三件事以前分散在三个程序里，现在是一个。**

## 十七、她说"换好了"，桌面上那个她却没动（2026-09-26 深夜）

这一节记的是他报的两个问题，两个都不是"程序坏了"。

### 问题一：她不会做动作

**现象**：他问「可以换个形态吗」，她答「好嘞，这就换上♪……怎么样，这一身，
比你想象中合身吧？」—— 话说得像真换了，桌面上那个她**一动都没动**。

我一开始以为是按键没发出去。查了聊天记录才发现真相：

```
他: 女仆吧
她: 好嘞，这就换上♪……这一身，比你想象中合身吧？
```

**她那句回复里，一个 `[表情:xx]` 标记都没有。**

从她的角度看，她"已经换了" —— 她在文字里换了衣服。
从桌面的角度看，什么都没发生。

> **她能做的只有"说话"。所有的"做事"，都得靠说话里带的约定。**
> 这就是规则 21 说的：文字里的动作不算动作。

**修法**：人格提示里原来只写了"换表情的标记写法是这样"，
太温和了 —— 她读完知道有这么回事，但没想到该用。改成：

- 开头第一句就点明：**在文字里写「（我歪了歪头）」那只是字，桌面上那个你一动都不会动**
- **没有标记，就什么都不会发生。不是"没生效"，是"根本没发生"。**
- 给了"什么时候**必须**写"的对照表：他说"换个形态"→ 挑对应形态的标记；
  "笑一个"→ 星星眼；"变回来"→ 连"消失"版一起列出来

改完再测，同一批问法：**6 句里 6 句都带标记了。**

**还加了一道兜底**：她偶尔会写错名字（实测写过"眯脉"，
想说的是"眯眯眼"）。所以 `bridge.cjs` 里加了个"猜一下"（`大概查表`）：

```
眯眼   → 眯眯眼  Alt+9   ←猜的
女仆   → 女仆形态 Alt+3   ←猜的
流泪   → 流泪眼  Alt+-   ←猜的
妖精   → 妖精小姐 Alt+2   ←猜的
```

猜不出来的时候**打一行警告**，不装作没事 —— 宁可留个痕迹，不要悄悄不动。

### 问题二：桌面上那个她是"无表情版"

这是**我自己写错路径**造成的，而且这个错**从界面上完全看不出来**。

启动脚本里我写的是 `zhuochong\A-爱莉-无表情版`。
那个版本：

- 能开
- 能跟着打字
- 托盘图标正常
- **但按 Alt+Q 它不知道该干什么**

因为它的 `config.json` 里，键鼠模式下的 `l2d_expression` 是 **空的 `[]`** ——
也就是"没有把任何表情挂到按键上"。而且它 `img\standard` 里
**一个 `motion3.json` 都没有**，只有 1 个动作文件。

带表情版：**30 个表情动作全挂满**（4 个形态 + 22 个动作 + 3 段语音），
26 个动作文件、4 个表情文件。

**为什么这么久才发现**：因为它一切正常。程序开着、图标在、能打字 ——
没有任何一处报错。**"能跑"和"能干活"是两件事。**

顺手写了个工具，以后一眼就能看出来：

```
node tools\查桌宠配置.cjs
→ A-爱莉-带表情版  【键鼠模式】✓ 挂了 30 个表情动作
→ A-爱莉-无表情版  【键鼠模式】✓ 挂了 1 个表情动作
```

**坑中坑**：那个 `config.json` **不能直接 `JSON.parse`** ——
作者在里面写了 `//人律形态` 这样的注释，标准 JSON 不允许注释，一 parse 就报错。
所以要先"洗"一遍：把注释和尾逗号去掉，再解析。
（这段逻辑现在在 `查桌宠配置.cjs` 和 `启动桌宠.cjs` 里各有一份，
是同一个算法，改的时候记得两边都改。）

### 问题三：双击了，什么都没发生

**一个很容易被忽略的原因**：她这个程序有"只允许开一个"的设定
（不然会有两个托盘图标、两份记忆在打架）。

```js
if (!app.requestSingleInstanceLock()) app.quit()
```

**后果是：只要旧的还活着，新启动的那个会一声不响地自己退出。**
没有报错、没有窗口、没有任何提示 —— 看起来就是"双击了没反应"。

他关窗口的时候我加了"躲到托盘上"（`hide()`），
所以**窗口看不见了，程序其实还活着**。这时候再去启动新的，就撞上那把锁了。

**修法**：启动脚本开头先数一数 `electron.exe` 有几个，有就先 `taskkill` 收掉，
等 800 毫秒让系统收干净，再启动。并且把这个动作**打印出来**
（`[0/2] 发现上一轮的她还在跑（5 个进程），先收掉……`）——
他看得见，就知道不是我瞎搞。

> **"静默失败"是最难查的一类问题。**
> 程序不报错、不提示、就是不干活 —— 这时候要去想
> **"它是不是压根没跑起来"**，而不是一直盯着"它为什么跑不对"。

### 这一晚真正的教训

三件事，同一个根子：

| 现象 | 我一开始以为 | 其实是 |
|---|---|---|
| 她不做动作 | 按键没发出去 | **她压根没发标记**（她只是"说"了要换） |
| 换了也没效果 | 快捷键被关掉了 | **桌宠是无表情版**，一个表情都没挂 |
| 双击没反应 | 脚本坏了 | **旧的还活着**，新的被"只许开一个"挡回去了 |

三个都是我**没往那一层想**。所以这次的收获不是三个修法，是三条思路：

1. **她说做了 ≠ 她做了** —— 她的输出要看"有没有带约定"，不能看"话说得像不像"
2. **能跑 ≠ 能干活** —— 程序正常，不代表它加载的那份数据是对的
3. **没反应 ≠ 跑错了** —— 先确认它到底跑起来没有，再谈跑得对不对

## 十八、"双击了没反应"的真正原因：我给错了文件（2026-09-26 深夜）

他发来一张截图：VS Code 打开着 `tools\启动桌宠.cjs`，光标停在最后一行（242 行）。
他说"按了出现这个"。

**真相**：他双击的是 `.cjs` 文件，而这台机器上 `.cjs` 关联的是 VS Code
—— **双击是"打开"，不是"运行"**。

这不是他的错，是我给了错的东西。我一直在跟他说"跑 `node tools\xxx.cjs`"，
可他是零基础，最自然的动作就是**双击**。而我从来没给过他一个能双击的东西。

> **给别人东西之前，先当作是他来用一遍。**
> 这句话他 2026-09-18 就教过我一次（那次是 `.cmd` 的换行符），我又犯了一遍。

### 修法一：给一个能双击的图标

做了三层：

```
桌面（你自己拖）
  └─ 爱莉希雅.lnk          ← 快捷方式，图标是那朵粉色小花
       └─ start-all.cmd    ← 双击它 = 全部启动（纯 ASCII）
            └─ start-all.cjs ← 真正的顺序安排
```

`start-all.cmd` 里只有一行 `node "start-all.cjs"`，**一个中文都没有**。
为什么这么小心 —— 见下面那条。

### 修法二：实测出"中文文件名在 .cmd 里真的会断"

我本来想省事，直接在 `.cmd` 里写：

```bat
node "tools\画图标.cjs" --ico
```

跑出来是这样：

```
Error: Cannot find module 'D:\新建文件夹\爱莉希雅\"'
```

**那行被从中间截断了**，路径只剩到引号前面。原因还是那个老问题：
cmd 按 GBK 解码 UTF-8 的 `画图标` 三个字，字节错位，把后面的引号吃掉了。

**所以规则要再加一条**：

> `.cmd` 里不能有中文 —— **不只是"内容里的中文句子"，连中文文件名都不行。**

办法：给那个中文名的工具配一个**纯英文名的替身**（`make-ico.cjs`），
`.cmd` 去叫替身，替身再去 `require` 那个中文名的模块
（Node 读 UTF-8，处理中文文件名没问题）。

**这一条是实测出来的，不是推理出来的。** 我原本以为"以前那个
`启动爱莉希雅.cmd` 里也有中文，它不是好好的吗" —— 结果一测就断。
以前那个之所以没事，是**运气**，不是规律。

### 修法三：一个自己写出来的蠢 bug

`start-all.cjs` 里我写了：

```js
function 说(...行) {
  for (const 行 of 行) console.log(行)   // ← 炸
}
```

跑到最后几行时报：

```
ReferenceError: Cannot access '行' before initialization
```

**参数叫 `行`，循环变量也叫 `行`** —— 在同一个名字初始化之前就用了它。
前半段一直没报错，因为它压根没被调用过；到最后打印"全部起来了"才炸。

> 变量名撞车这种事，编译器不一定当场告诉你，**要跑到那儿才知道**。
> 所以：**改了代码，就得把整条路走一遍**，不能只测开头。

### 这一晚最后的样子

| 想干什么 | 双击哪儿 |
|---|---|
| 全部叫起来 | 桌面上那个粉色小花图标（或者工作区里的 `爱莉希雅.lnk`） |
| 只叫桌宠和她 | `爱莉希雅\tools\start-elysia.cmd` |
| 重画图标 | `爱莉希雅\tools\repair-icon.cmd` |
| 在桌面建图标 | `爱莉希雅\tools\make-icon.cmd` |
| 查桌宠挂了几个表情 | `node tools\查桌宠配置.cjs` |
| 看她会不会真的做动作 | `node tools\测表情.cjs` |

**`.cjs` 文件永远不要双击**（会打开编辑器）。要双击的一律是 `.cmd`。

## 十九、桌宠起来了、表情也会换 —— 以及"慢"是慢在哪儿（2026-09-26 深夜）

两件好事，和一条新的规矩。

### 拉桌宠这件事：换了个办法就通了

之前一直是 `spawn(桌宠程序)` —— Node 直接启动那个 exe。
它失败得很安静（`spawn` 的错误是异步报的，`try/catch` 接不住），
而桌宠又装在中文路径下面：

```
D:\新建文件夹\zhuochong\A-爱莉-带表情版\Bongo Cat Mver.exe
```

**实测的证据很硬**：在我这个沙箱里 `spawn` 任何东西都会 `EACCES`（一律被挡），
可我换成"进到那个文件夹里、双击它自己的 `launch-pet.cmd`"，
Bongo Cat **真的起来了**（进程 6876）。同一个程序、同一台机器，只换了启动方式。

那个 `launch-pet.cmd` 里只有一行，而且**一个路径都没有**：

```bat
start "" "Bongo Cat Mver.exe"
```

因为它自己就住在桌宠的文件夹里 —— **工作目录就是那个中文路径**，
命令行文本里一个中文都不出现。这就是它稳的原因。

> **规律：中文路径只要"待在工作目录里"就没事，
> 一旦被拼进命令行文本就会出事。**
> （同一个坑这一天咬了两次：启动 Electron 那次报
> "文件名、目录名或卷标语法不正确"，也是这个。）

现在 `启动桌宠()` 会依次走三条路，每条都留话在日志里：
`launch-pet.cmd` → 系统的 `shell.openPath` → 老的 `spawn`。
他的机器上第二条就成了，日志里写着 `✓ 桌宠起来了`。

### "慢"是慢在素材，不是慢在我们

他说"她换了，只不过很慢，现在才加载出来"。我去量了一下 Bongo Cat 的素材：

```
standard 模式  19.8 MB   （模型 14.5 MB）
keyboard 模式  24.0 MB   （模型 14.7 MB）
gamepad  模式  18.8 MB   （模型 15.1 MB）
                 ─────
                 62.6 MB   光一张贴图 texture_00.png 就 8.7 MB
```

**它启动时要把三个模式的模型全读进来，62 MB。** 这一下省不掉 ——
那是它的设计，不是我们能改的。（唯一能省的是把不用的模式素材藏起来，
但不值当，也容易把它弄坏。）

> 记住这个数字。下次再觉得"卡"，先问一句：
> **是我们慢，还是它自己在加载？**
> 分清楚这个，才不会去优化一个本来就没问题的地方。

### 新规矩：不许把"她记得做"当成"她会做"

原来表情是这么触发的：她在话最后写 `[表情:星星眼]`，程序看到标记才去按键。

我测了六句问法，**六句都写了标记**，我就以为好了。结果他真跟她说
「可以换成女仆形态吗」，她答：

> 「行，我这就换。……不过说真的，你是不是偷偷在试所有形态呀？」

**标记又是一个都没有。** 桌面上那个她一动没动。

这是同一个道理的第二次现形（第一次是她说"我这就换上"而没写标记）：

> **"她说要换"和"她真的换了"是两件事。**
> 她在生成文字，不是在执行代码。**光靠提醒治不好** ——
> 提示词能提高概率，但不能保证。

所以加了 `脑\表情路由.cjs`：**程序自己读她的话，认出意思，替她按快捷键。**

```
她说「行，我这就换」+ 上文有"女仆"  →  程序按 Alt+3
她说「笑一个给你看」                  →  程序按 Alt+9
她说「别这样了，变回来」              →  程序按 Alt+1
```

**两条路都留着**：她自己写了标记就听她的（最准）；没写，程序兜住。

这里有个取舍要想清楚：**猜漏了和猜多了，哪个更糟？**

- 猜漏 → 桌面上那个她不动（就是他报的问题）
- 猜多 → 他说句正经话，桌面上那个她突然脸红（更讨厌）

所以我写了 `tools\测路由.cjs`，拿**两句都量**：
该认的 9/10（剩下那一句"行，我这就换"单独看没有形态词，只能靠上文，
我不打算为它去乱猜），**不该认的 5/5，一个都没误伤**。

> **凡是要"猜"的地方，就得有量它的办法。**
> 不然你只是把一类 bug 换成了另一类。

### 还有个小设计：形态要"记住"

女仆形态是**一直保持**的。要是每说一句都重按一次 Alt+3，
动画会从头播一遍，看着像抽风。所以程序记着 `当前形态`，
认出一样的就跳过。

**"一直保持的东西"和"按一下动一下的东西"要分开对待** ——
星星眼是后者（说一次做一次），形态是前者（说了就一直算）。

## 二十、"还没出现"不等于"失败了"（2026-09-26 深夜，收尾）

他报"他会启动两个桌宠"。查下去，是我自己写的兜底逻辑把程序开了两遍。

### 日志里写得明明白白

```
  → 用 launch-pet.cmd 拉起桌宠（最稳的一条路）
  （没起来，换下一条路）          ← 它其实起来了
  → 改用系统打开的方式…… ✓ 桌宠起来了   ← 于是第二只
```

我当时是这么写的：**每条路走完等 2 秒，问一句"在不在"，不在就换下一条。**

问题是桌宠启动要读 62 MB 素材，**好几秒才出现在进程表里**。
2 秒的时候问，当然说"不在"。于是我以为路一失败了，又用路二开了第二个。

> **"还没出现"和"失败了"是两件事。**
> 因果推断里最容易被忽略的一种错：**把"我还没看到"当成"它没发生"。**

这已经是同一晚第三次栽在"时间"上了（前两次是"她说换了"和"我以为起来了"）。
所以我把它写成本子上的规矩：

- **要等一个东西出现，就轮询到它出现为止**（每 400 毫秒问一次，最多 10 秒），
  不要"睡固定时长再看一眼"
- 固定时长的那个数字，早晚会不够

### 第二个错误：一个安静答错的判断

`有进程()` 原来用的是：

```js
tasklist /FI "IMAGENAME eq Bongo Cat Mver.exe" /NH
  → 输出.toLowerCase().includes("bongo cat mver.exe")
```

看着没问题：名字带空格，我加引号了。

**可它对带空格的名字答不准。** 而且它还有一层危险：
**如果命令本身出错（比如被拒绝访问），catch 会返回 false** ——
于是"查不出来"和"没在跑"变成同一个答案。

**一个判断如果会把"我不知道"说成"没有"，它就会在最要紧的时候骗你。**

改成问 PowerShell 的 `Get-Process`：那是按**进程对象**查的，
不经过"字符串匹配"这一层，空格、引号、代码页都碰不到它，稳。

### 第三件事：与其判断准，不如收尾稳

多试几条路这种写法，天生带一个风险：**前一条其实成功了、只是慢**。
我加了一道收尾：**不管走的哪条路，启动完都数一遍，多了就收掉，只留最早那只。**

> **判断和收尾，是两道不同的保险。**
> 判断再准也可能有想不到的情况；收尾是"不管前面发生了什么，最后都收拾干净"。

### 今晚最后的样子（都实测过了）

```
点桌面上那朵粉色小花
  → 她弹出小窗口
说一句话
  → 她一边想一边把字写出来
  → 说完自己出声（她的声音，不是合成的机器音）
  → 桌面上那个她按话里的意思换表情 / 换形态
```

日志里那一行是关键证据：

```
✓ 让她做了（她写的标记）：动画：超级爱莉  (Alt+]) —— 直接发出
```

**`直接发出`** —— 说明按键注入这条路在他机器上是通的（我这边沙箱里永远是
`EPERM`，只能写队列）。一整晚卡的都是两头：**她没说要动**、**桌宠没起来**，

1. **她说做了 ≠ 她做了**（她的输出要看"有没有带约定"）

3. **还没出现 ≠ 失败了**（这句话被三件事分别验证过一遍）
