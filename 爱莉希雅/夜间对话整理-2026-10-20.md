## 一、给 AI 一个手机（手机 GUI Agent）

### 截图里的实现是什么
第二张截图（手机显示 Windows 桌面 + B站图标 + "手机通了，我能看见自己的桌面了"）大概率是**把电脑画面推到手机**（ToDesk / 向日葵 / Moonlight / Steam Link 这类）—— 那是「人看电脑」，**不是「AI 玩手机」**。

### 真正要做的三层
```
① 看   adb exec-out screencap -p > screen.png        （或 scrcpy，延迟 30-60ms）
② 想   DeepSeek v4.1 flash 视觉：看懂屏幕 + 输出动作（grounding）
③ 动   adb shell input tap / swipe / text / keyevent
```

更稳的输入方式：**uiautomator2**（拿控件树，不靠像素猜坐标）。

### 模块形态（届时落地）
```
脑\手机.cjs
  ├ 看屏幕()    → adb screencap
  ├ 点(x,y)     → adb shell input tap
  ├ 输入(文字)  → adb shell input text
  ├ 返回/主页   → adb shell input keyevent
  └ 当前应用()  → adb shell dumpsys window | findstr mCurrentFocus
```

### 建议先模拟器
MuMu / 雷电 → `adb connect 127.0.0.1:7555`
好处：不占真手机、出事直接关、可快照回滚、分辨率固定坐标稳定。
**代码不变，之后只改 `adb connect` 的目标 IP 就能指到真机。**

### 视觉模型选型（讨论过）
| 方案 | 说明 |
|---|---|
| **DeepSeek v4.1 flash 视觉** | 用户确认可用；不用显卡、成本低 → **首选** |
| Qwen2.5/3-VL、UI-TARS、OS-Atlas | 开源 grounding 强，但 8G 显存跑 7B 量化勉强 |
| GPT-4o / Claude Computer Use | 效果最好，要钱且上传截图 |

⚠️ DeepSeek 的**文本**模型做不了这个 —— 它看不见屏幕。

### 三个必须做的安全件
1. **急停**：全局热键 → `keyevent 3` 回主页并中止循环
2. **预算**：每轮最多 N 步、总共最多 M 分钟
3. **日志**：每个动作记进情景记忆（"今天在B站看了个视频"）

### 成本提醒
视觉模型每轮一张图：30 秒一轮、玩 10 分钟 = 20 张图。
省钱：前后截图做**像素差**，只在画面明显变化时调模型；或小模型做 grounding、大模型只做决策。

## 二、真机 vs 模拟器

用户问：**"如果我给她一个真的手机呢"**

### 连接方式（Android 11+ 无线调试）
```
手机：开发者选项 → 无线调试 → 配对（出现 IP:端口 + 配对码）
电脑：adb pair 192.168.x.x:PORT   ← 输入配对码
      adb connect 192.168.x.x:PORT
```
必须做：**路由器固定 IP（DHCP 保留）** + 关自动锁屏 + 关 Wi-Fi 休眠。

### 安全：ADB over TCP **无认证**
- ❌ 绝不能把 5555 映射到公网
- ✅ 只在家庭内网
- ✅ 最好独立 VLAN / 访客网络隔离
- ✅ 用完 `adb disconnect`

### 别用主力机
| 风险 | 说明 |
|---|---|
隐私 | 相册、微信、银行 App 全在屏幕上，截图会上传给视觉模型 |
误操作 | 可能点到付款、删文件、发消息给朋友 |
封号 | B站/QQ 检测到自动化可能封号 |

建议：旧手机恢复出厂设置，只装要玩的应用；或用 Android「工作资料」（Island / Shelter）隔离。

### 真机能做、模拟器做不到的
刷 B站、听歌、看小说、逛淘宝（真实 App + 真实账号）、真实网络与推送、24 小时挂着不需要开电脑。

### 建议顺序
```
第一周  真机 + 只读（只看不点）→ 验证视觉模型准不准
第二周  开放点击，但白名单（只允许 B站/音乐/浏览器）
第三周  加预算和熔断（连续 3 次点空停止；单次会话 ≤ 20 分钟）
```
**但先别急着上真机** —— 模拟器上调通更快，代码不用改。

## 三、服务器部署（阿里云 99 元 / 年）

用户说："**我想的是把我的项目放在服务器上跑，这样就能随时运行，不占用我的电脑**"

### 架构：脑壳分离
```
服务器（Linux，无 GPU）  脑：对话 / 记忆 / 工具 / 渠道适配
        ↕ WebSocket
本机（Windows）          壳：Live2D 桌宠 + 语音 + 屏幕
```
- Live2D 留在本机（桌宠是给人看的，跑无头服务器没意义）
- 模型全走 API → **服务器不需要显卡**
- 通过 WebSocket 同步：手机上聊的话，本机桌宠也有反应

### 阿里云 99 元（一般 2 核 2G / 3M / 40G）能力分配
| ✅ 能跑 | 🟡 勉强 | ❌ 不能 |
|---|---|---|
对话核心（200-400MB）| 本地 ASR（SenseVoice，2 核跑满且慢，建议换云端）| Live2D 桌宠（要 GPU + 桌面窗口）|
记忆系统（SQLite + API）| 本地 embedding（ollama 在 2G 会 OOM，建议词法检索或云端）| 本地 TTS（GPT-SoVITS 要显卡）|
日记 / 定时任务 | 图片处理 / 图层操作（本来该在本地）| 桌面自动化（物理上在你的 Windows）|
渠道适配（Telegram / NapCat 200-500MB）| | Android 模拟器（**99 元那台无嵌套虚拟化**）|
联网搜索 / 视觉决策 | | |

### 渠道选型
| 渠道 | 做法 | 风险 |
|---|---|---|
**Telegram** | 官方 Bot API，5 分钟接好 | ✅ 无风险，**先跑通它** |
**QQ** | NapCat / LLOneBot（协议端） | ⚠️ 中，可能封号，用小号 |
**微信** | 官方「企业微信应用」/「微信客服」 | ✅ 合规，需企业认证 |
**微信协议端** | wechaty / padlocal 之类 | ❌ 高，封号 + 法律风险，**不碰** |

### 先在本机做渠道层，不先动服务器
写 `脑\渠道.cjs`（统一接口：收到消息 / 发出消息）→ 接 Telegram adapter → 验证"手机发一句、她回一句、记忆正常写入"。
**这一步通了，搬服务器只是换部署方式（Docker + systemd），代码不用重写。**

### 三个提前要想的
1. 服务器境内还是境外（境内快、需备案；境外免备案但 QQ 慢）
2. 数据放哪：记忆和日记是私密数据 → 服务器本地 SQLite + 定期同步回本机备份，别用第三方云数据库
3. 掉线怎么办：离线消息队列 + 健康检查（服务器挂了本机要提示）

### 三个已知的坑
1. **2G 内存偏紧** → 必开 swap（2G），否则 Node + NapCat 一起跑会 OOM
2. **3M 带宽** → 文字够，传语音/图片会慢；**手机 Agent 的截图别走服务器**
3. **99 元通常是首年价**，续费会涨；域名 + 公网要备案

## 四、B站相关项目调研（五个）

| 项目 | 干什么 | 对爱莉希雅的价值 |
|---|---|---|
[Yuuyuko-uu/dsh-bili-subagent](https://github.com/Yuuyuko-uu/dsh-bili-subagent) | 派子代理刷B站、读字幕挑内容、用伙伴口吻评论@你 | ⭐⭐⭐ **子代理隔离上下文**的模式最值得抄 |
[YOYOLnFu/dsh-bili-pond](https://github.com/YOYOLnFu/dsh-bili-pond) | 每天捞几条值得看的、写日报@你 | ⭐⭐ 主动陪伴的日报形态 |
[InariNGT-Ofiicial/dsh-bili-humanism](https://github.com/InariNGT-Ofiicial/dsh-bili-humanism) | 分层取稿→证据化理解→可修正记忆→本地交付 | ⭐⭐⭐ 和记忆分层同构，值得对标数据结构 |
[c1overzz/dsh-bili-scroll](https://github.com/c1overzz/dsh-bili-scroll) | 每天刷一轮、读字幕原文判断、值得的评论@你 | ⭐⭐ 判据："值不值得占用你一次注意力" |
[Alterssss/dsh-bili-whale](https://github.com/Alterssss/dsh-bili-whale) | 自己醒、六路理解、每天最多@3次、两本日记 | ⭐⭐⭐⭐ **人格设计最成熟**，用户最喜欢 |

### 各项目要点

**dsh-bili-subagent**：子代理读字幕挑出值得的，把详细内容汇报回来，伙伴再**用自己的口吻**评论 @ 你/私信你。
→ 关键：视频字幕几万字，直接进主对话会撑爆上下文；subagent 消化完只回摘要，主对话保持人格干净。

**dsh-bili-pond（B站鱼塘）**：每天派鱼下去捞几条值得看的上来，写完日报 @ 你。→ 主动陪伴 P1 的现成参考形态。

**dsh-bili-humanism**：分层取稿 → 证据化理解 → 可修正记忆 → 本地交付；v1.1 加了"人类开关"授权历史与收藏，默认关闭。→ 和 P1 记忆分层几乎同构。

**dsh-bili-scroll**：按关键词搜近几天视频 → **逐条读字幕原文判断（不看摘要）** → 写 Markdown 报告（每条含"为什么值得"+ 自己的一句话）→ 值得的评论 @ 你。
- 判据只有一句：**值不值得占用你一次注意力**
- 每轮 @ 默认 1 条（可调到 20）
- 可在**峰谷时段自动跑**省 token
- 每条的段首固定写 `### BV号` → **插件靠数这些标题行知道今天挑了几条**（用固定格式让程序可数，不用额外元数据）
- README 里"装不上先看五条"全是用户实测撞过的坑，成熟度比其他几个高一档
- 依赖：Python 3.10+/uv、B站 cookie、本地转写要 Whisper（538MB）

**dsh-bili-whale（用户特别提到）**：
- **在设定窗口里随机时刻自己醒**，30% 概率说"今天不想看" → 打破定时任务感
- **六路看懂一条视频**：封面 / 简介 / 官方字幕 / **弹幕热区** / 热评 / 抽帧看画面
- **每天最多 @ 你 3 次，过不了评分一条都不发**
- **写两本日记：一本给你，一本不给你** ← 最重要的一条
- 评论区 / 直播间有人找它会回；**回陌生人要先写草稿等你审**
- **沉默 3 天开始衰减，7 天彻底不分享 —— 但日记照写**
- 需要：Windows/macOS + DSH + 一个 B站小号

## 八、云端主要用途：电脑关机时也能用 QQ 聊天 + 主动刷视频分享

用户的原话意思：**"我云端服务主要是想电脑不开机的时候也能用 QQ 和她聊会天，或者她主动去刷刷视频分享给我。"**

### 结论：可以满足，而且这正是「服务器当大脑」的典型形态

```
电脑关机 → 服务器照常在跑 → 手机 QQ 发消息 → 她回你
                          → 定时醒来刷视频 → 觉得好的发给你
电脑开机后 → 本地只是多一块「屏幕」（Live2D 桌宠），不接管记忆
```

### 服务器上要跑什么

| 组件 | 作用 | 资源 |
|---|---|---|
Node Agent（`脑/`） | 对话、记忆、判断、调度 | 200-400 MB |
NapCat（QQ 协议端） | 收发 QQ 消息 | 200-500 MB |
SQLite | 唯一记忆库 | 几十 MB |
B站抓取 | 搜索、字幕、评论区 | 极低（API） |
DeepSeek API | 判分、写评论 | 极低（网络） |

合计约 **1-1.2 GB / 2G**，能跑，**不需要显卡**。

### 部署形态

两个容器 + 一个挂载卷（`agent` + `napcat`），登录态和 SQLite 都挂持久卷，重启不丢。

### QQ 渠道的现实问题（存疑部分）

| 问题 | 现状判断 |
|---|---|
| NapCat 需要扫码登录一次，之后保持会话 | 掉线要**手动重扫** → 所以用**小号**，别用主号 |
| 封号风险 | 小号 + 控频（别一秒几条）+ 只私聊不刷群 |
| **建议双通道** | QQ 为主、**Telegram 备用**（Bot 永不掉线，QQ 挂了还能找到她） |
| ⚠️ 存疑 | NapCat 长期稳定性、QQ 风控策略会变，**需要实测多久掉一次**，掉线能否自动重连 |

### 主动刷视频分享（服务器端流程）

```
定时器（随机窗口，30% 概率跳过）
  → B站 API 搜索候选
  → 逐条取字幕/简介/热评（可选抽帧）
  → DeepSeek 判分：值不值得占用她一次注意力
  → 过阈值：生成「为什么值得」+ 自己的一句话 → 发 QQ
  → 不过阈值：一条都不发
  → 每天硬上限 3 条
```

⚠️ **限制与存疑**
- 抽帧要 **ffmpeg**（吃 CPU + 流量），2 核机器上要限次数，或者不抽
- 3M 带宽够传封面和小文本，**别传视频**
- B站用小号 cookie，高频会风控 —— **具体阈值未知，需要实测**
- 视频内容动辄几万字字幕，**建议用子代理消化后再回主对话**（抄 bili-subagent 的做法）

### 语音：服务器无显卡 → 三个选择

1. **不做语音**，只发文字 + 图片（最简单，建议先这样）
2. **云端 TTS**（阿里云/火山，按量计费）
3. 本机生成（依赖电脑开机，**违背初衷**，不推荐）

### 电脑开机后的衔接

```
开机 → 拉服务器快照（VACUUM INTO 后的 db）→ 本地 SQLite 副本（只读）
     → Live2D 桌宠连服务器 WebSocket，读同一份记忆
     → 桌宠只是「多一块屏幕」，不接管记忆
```

同步方案：**先做整库快照下载**（10 行代码，`VACUUM INTO` 保证一致），库超过 200 MB 再考虑增量同步（软删除 + 分页 + 断点）。
三个必须处理：开机没网（用旧副本 + 后台重试）、同步断点（记 `last_sync_ts`）、服务器挂了（只读 + 提示离线）。

### 最小可行版本（建议顺序）

```
第 1 步  服务器跑通 Node Agent + SQLite，回一条固定话
第 2 步  接 Telegram（10 行代码，验证整条链路）
第 3 步  换 NapCat 接 QQ（要扫码，风险在这）
第 4 步  加「主动刷视频」定时任务（先只发你，不评论）
第 5 步  加「值不值得」判分 + 每天 3 条上限
第 6 步  本机开机同步 + Live2D 连上
```

**第 2 步是关键**：Telegram 通了说明「外部消息 → 她 → 回复」整条链路是好的，之后换 QQ 只是换 adapter。

### 一句话风险提示

这套跑起来之后，**她就真的独立存在了** —— 手机关着她也在跑、可能主动找你、可能有你不知道的日记。这是想要的效果，但要提前想好：**日志、健康检查、一个能远程停机的接口**。
