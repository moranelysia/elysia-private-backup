# S-16D3 C3C4：真实连接受控路径与假 HTTP 验收

## 实现范围

`脑/模型连接.cjs` 增加显式受控发送器；领取后旧同步/异步绑定与旧 `要一轮` 均拒绝在同一连接上使用。发送器校验消息、模型预算和请求 UUID，使用原固定端点、超时、响应字节限制和脱敏错误。它不自行记账，必须由受信隔离调度器持有并调用；模块级内部接口不是防任意本机恶意代码的安全沙箱，不得向渲染进程或不受信插件暴露。

`core/隔离一次性假发送.cjs` 的调度逻辑增加显式真实连接适配：在格式3虚构 Worker 上先组合提交预留和 started，确认可能发送、绑定并消费一次性内存能力，再调用连接；响应验证后组合提交结果与 succeeded，确认后才返回。结果或网络未知不自动重发、不伪造成功；同一连接/调度器失败后封闭。首次预留会固定 UUID，与轮次和用量一致。原有固定假传输路径继续保留。

本步测试中真实连接的 transport **全部显式注入假 HTTP**，凭据和正文均虚构；该新路径未接生产渠道或桌面程序。模块接口本身在未来被受信调用者配置真实凭据及 transport 后具备发网络请求的能力，本轮没有执行真实请求。低层模块和虚构 Worker 可供受信 Node 代码直接调用，不能把此隔离当成任意代码沙箱。需要保守保留可能已发送状态，即使崩溃实际发生于 HTTP 调用前。
