# C-13 本人身份与渠道外发权限

日期：2026-10-25。实现：`脑/渠道权限.cjs`。验证：`tools/测渠道权限.cjs`。

本步在C-11契约和C-12假适配器上增加权限策略及调用守卫。只使用进程内配置和虚构身份；未接main.js、真实模型、真实渠道、登录认证或服务器。依赖仅为渠道契约，不读取本机账号、配置文件或正式记忆。

## 1. 默认权限

| 场景 | 默认结果 |
|---|---|
| 没有任何本人绑定 | 拒绝接收处理与外发 |
| 精确绑定的本人私聊 | 允许交给处理函数，并产生本次消息的回复许可 |
| 昵称相同、正文自称本人、其他发送者 | 拒绝；消息内容不能授予权限 |
| 本人在其他未绑定的渠道、账号或私聊 | 拒绝，不自动跨渠道继承 |
| 所有群聊 | 拒绝，包括群内本人消息 |
| 陌生人私聊、好友申请、转账、外部评论或其他外部操作 | 没有开放入口，不能凭私聊回复权执行 |
| 发给本人的主动消息 | 默认拒绝；必须单独设置该绑定的允许主动发送=true，并满足平台能力 |
| private日记或非法消息结构 | 拒绝，shared标签不能代替正文来源检查 |

群聊和陌生人的消息在调用处理函数之前拦截，不能先读取记忆、生成回复后才决定是否发送。此处的“处理函数”仅为测试固定回复，真实核心尚未接入。

## 2. 本人绑定配置

```js
const { 创建渠道权限 } = require('./脑/渠道权限.cjs')
const 权限 = 创建渠道权限({
  绑定: [{
    端点: { 渠道: 'fake', 账号: 'local-fixture' },
    本人编号: 'person-fixture',
    私聊会话编号: 'dm-fixture',
    允许主动发送: false,
  }],
})
```

全部为虚构值。每条必须准确包含这四个字段；编号按C-11字符串规则校验；主动许可必须是布尔值。最多64条，同一渠道/账号/私聊会话不能绑定两个不同身份或重复配置。

配置只能由受信本机/服务器管理入口提供，不得从聊天正文、模型工具参数、昵称或客户端自报“主人”字段生成。更新绑定是管理操作，本模块没有将其暴露为IPC、HTTP或聊天指令。

身份由渠道、机器人账号、私聊会话、发送者四项精确匹配。当前平台事件是否真实、连接是否认证由后续实际适配器负责；仅把JSON中的发送者编号改成本人不能证明真实身份。守卫固定创建时适配器的端点，另一个已绑定端点也不能借它上报消息或外发。

绑定只是准入白名单，不是对话索引，不创建或合并核心会话；C-14再实现会话映射。

## 3. 策略接口

`创建渠道权限({绑定=[], 回复许可毫秒=600000, 取现在=()=>new Date()})`：默认无本人；许可默认10分钟，上限24小时；测试时钟必须返回有效Date。

| 接口 | 行为 |
|---|---|
| 审查接收(消息) | 校验结构与本人私聊；成功返回允许、固定代码和回复许可 |
| 审查发送(消息, {回复许可}) | 校验目标、用途和当前绑定；普通回复必须有本次来源许可，主动发送检查独立开关 |
| 审查取消(请求, {回复许可}) | 限当前绑定本人的同一端点/会话操作，具体目标任务仍由适配器核对 |
| 更新绑定(列表) | 先完整验证再原子替换内存配置，撤销全部旧许可并通知守卫 |
| 订阅变更(处理) | 管理内部变更监听，返回取消监听函数；监听异常不透传 |
| 取状态() | 仅返回关闭状态、绑定数、启用主动发送数，不返回账号、正文和令牌内容 |
| 关闭() | 幂等清空绑定与许可、通知变更并释放监听，关闭后不能重新启用 |

策略拒绝仅返回`{允许:false,代码}`，固定代码包括POLICY_CLOSED、INVALID_CONTRACT、GROUP_DISABLED、OWNER_NOT_BOUND、PROACTIVE_DISABLED、REPLY_CONTEXT_INVALID和REPLY_CONTEXT_MISMATCH。无效配置抛出固定错误，不用空配置静默覆盖现有有效绑定。

## 4. 本次回复许可

回复许可是本策略实例生成的冻结对象，来源保存在WeakMap中，只含端点、会话、本人、原消息编号和许可时刻，不保存正文或附件。许可不能通过JSON复制、任意构造对象、另一个策略实例或另一个渠道冒用。

发送必须仍指向原端点、原会话、原本人及原消息编号。旧消息许可不能换成另一条消息的回复，也不授予主动发送权。许可超时、时钟倒退、关闭或合法配置更新后失效；重新添加同一绑定也不恢复旧许可。

令牌只在服务进程内流转，不发给模型、渠道、日志或客户端。重启/跨进程后不可复用；C-15将来恢复队列时须从受信来源重新审查，不能序列化空对象冒充原许可。许可有效期独立于平台回复窗口，二者都满足才可发送。

## 5. 权限守卫

`创建渠道权限守卫({适配器, 权限, 取现在})`组合策略与已有适配器，提供C-11的取能力、订阅接收、发送、取消及关闭接口：

- 订阅接收先核对固定端点、结构及本人私聊，再把消息和`{回复许可}`交给处理函数。
- 发送重新检查当前权限；拒绝时在适配器之前返回标准failed/FORBIDDEN，不创建实际发送尝试。格式错误遵循C-11拒绝，不默默修复。
- 允许主动发送只代表本机策略许可，不能替代平台主动发送能力；能力不足仍由适配器明确拒绝。
- 取消也要求有效的本人会话许可；不能只凭知道请求编号就跨身份停止任务，适配器还须核对具体任务归属。取消已sent/unknown的任务不伪装为撤回。
- 合法绑定更新或策略关闭时，守卫向正在进行的调用传播AbortSignal；本步验证fake尚未交付的暂缓任务能够终止。已交付消息或不支持中止的真实平台操作不能据此保证撤回。
- 外部AbortSignal不携带reason外发；任务结束后清理监听器。守卫关闭释放自己的订阅和中止控制，不擅自关闭共享的底层适配器。
- 适配器抛错或返回不匹配的请求/端点回执时，统一返回unknown/DELIVERY_UNKNOWN，不回显原始异常、不自动重发。

能力快照表示平台能力，不是用户授权。真正允许发送需要同时满足本人绑定、用途许可、消息来源和平台能力/时间/附件限制。

权限在守卫调用发送时检查；后续队列必须在出队实际调用时重新走守卫。许可自然过期没有后台计时器，不承诺回滚已经交给平台执行的操作。配置更新会主动传播中止，但不替代C-15的持久任务状态与网络去重。

## 6. 本地组合示例

```js
const { 创建假渠道适配器 } = require('./脑/假渠道适配器.cjs')
const { 创建渠道权限守卫 } = require('./脑/渠道权限.cjs')
const 适配器 = 创建假渠道适配器()
const 守卫 = 创建渠道权限守卫({ 适配器, 权限 })
守卫.订阅接收(async (收到, 上下文) => {
  // 收到这里才允许未来的核心读取上下文；本轮只使用固定测试回复。
  await 守卫.发送({
    版本: 1, 端点: 收到.端点, 会话: 收到.会话,
    接收者编号: 收到.发送者编号, 请求编号: 'reply-' + 收到.消息编号,
    用途: 'reply', 回复消息编号: 收到.消息编号,
    创建于: new Date().toISOString(), 截止于: null,
    可见性: 'shared', 正文: '这是受控的本地固定回复。', 附件: [],
  }, 上下文)
})
```

外部调用必须经过守卫；持有底层适配器的受信代码仍可直接调用它，因此不能把裸适配器、管理方法或许可对象暴露给模型/客户端。这是本地模块边界，真实网络身份认证在Q-11/C-16验证。

日记正文仍先通过现有shared外发闸门，不能因为请求写了shared就跳过来源过滤。现有聊天记忆、临时对话和文件/工具权限没有由本步改变；C-14会话映射、C-15队列去重、S-12真实核心和所有真实账号仍未开始。
