# 爱莉希雅项目分析

分析时间：2026-10-08

产品长期目标见 `产品目标.md`：项目定位为具有聊天、工作、学习陪伴三种模式，可接入社交软件、声音和视觉能力的桌面陪伴型 Agent。

## 实施进度

- 已增加统一配置入口，角色卡、学习区、运行数据、缓存、桌宠和语音地址不再散落在各模块。
- 已增加干净迁移生成器；生成物不带旧人格、聊天、附件、用量、授权或 API Key。
- 已用真实路径解析封住 junction / 符号链接绕过白名单的问题。
- Shell 已从同步执行改为异步执行，运行命令时不再阻塞 Electron 主进程。
- 已从主进程抽出设置存储和 Windows 进程检测；设置改为原子保存，避免半写入文件。
- 核心测试已经可以在完全空白的迁移副本上运行，不要求预先存在旧聊天或长期记忆。

## 1. 这不是一个项目，而是三层演进

工作区里实际包含三套互相关联的东西：

1. **DSH 角色 Agent**：由 `elysia.cosplay.v2.json`、`AGENTS.md` 和 `.dsh/skills/` 组成，解决人格、长期背景和角色知识。
2. **声音与桌宠整合层**：`tools/voice/`、`start-all.cjs`、`start-pet-service.cjs` 把 GPT-SoVITS、Bongo Cat 和聊天入口接起来。
3. **独立 Electron 桌面助手**：`爱莉希雅/` 是当前真正成型的程序。它已经不依赖 DSH 完成对话，自己负责模型调用、记忆、工具、权限、聊天界面和学习模式。

`cyrene-源码/` 是参考实现，不是当前独立版的运行依赖；`工具研究/` 是从参考项目提取出来的研究材料。

## 2. 当前独立版的运行链路

```text
renderer/index.html + chat.js
        │ window.爱莉.*
        ▼
preload.js（只暴露指定 IPC）
        │
        ▼
main.js（窗口、托盘、确认卡、模式、对话切换）
        │
        ▼
脑/对话.cjs（提示词、历史、流式请求、工具循环）
        ├── 记忆.cjs / 用量.cjs / 附件.cjs
        ├── 提示词.cjs / 学习进度.cjs / 学习任务.cjs
        └── 工具表.cjs
              ├── 查、读、列、找
              ├── 写、跑
              ├── 派（子代理）
              └── 任务
```

模型没有使用 API 原生 function calling，而是在文本里输出 `[查:...]`、`[写:...]` 等标记。程序解析标记、执行工具，再把结果送回模型，最多循环三轮。这种方案保住了 DeepSeek 的提示词缓存，但工具参数的可靠性和可扩展性弱于结构化调用。

## 3. 已经做得比较好的部分

- Electron 渲染进程启用了 `contextIsolation`，关闭了 `nodeIntegration`，本地文件和系统能力只通过 preload 中明确列出的 IPC 开口暴露。
- API Key 没写进源码，按“项目钥匙文件 → 环境变量 → DSH 凭证”的顺序寻找，日志只显示头尾。
- 文件操作有独立的路径边界：读写白名单、禁地、只读目录、文件大小限制分开处理。
- 写文件默认需要确认；执行命令每次都需要确认，而且不能永久放行。
- 对话、事实、共同经历、附件、用量、学习进度和“上次没干完”被拆成不同存储，语义清楚。
- 多对话按段隔离，同时共享长期记忆；模型也按对话保存，产品行为已经比较完整。
- 测试并非只有表面覆盖，很多测试专门记录曾经出现过的真实回归，例如路径穿越、工具结果丢失、权限误放行和附件重名覆盖。

## 4. 主要问题

### 4.1 目录结构和本机路径绑定严重

程序把“项目目录的上一层”直接认作工作区，并从那里读取角色卡与学习区。桌宠目录、GPT-SoVITS 路径、部分提示词和启动说明还写死了 `D:\新建文件夹` 或 `D:\GPT-SoVITS`。

因此单独复制 `爱莉希雅/` 不能构成完整可运行副本。现在整理出的 `_完整工作区源码/爱莉希雅/` 保留了原有相对结构，但要真正做到可迁移，仍应增加统一配置文件或环境变量，把工作区、桌宠、语音服务和角色卡位置集中管理。

### 4.2 路径安全的文件系统链接问题（已处理）

`脑/路径安全.cjs` 使用 `path.resolve` 和 `path.relative` 防止 `..` 穿越，这能挡住普通路径穿越，但没有调用 `realpath` 检查符号链接或 Windows 目录联接。

现在会从最近一个存在的父目录解析真实地址，再用真实位置检查白名单和禁地；现有文件与尚未创建的新文件都覆盖。测试会创建一个真实 junction 指向 `.cache`，确认读写均被拒绝。

### 4.3 命令执行阻塞 Electron 主进程（已处理）

`脑/工具/命令工具.cjs` 已改为异步 `execFile`，继续保留 60 秒超时、8 MB 进程缓冲、30 KB 对话输出上限和逐次确认。测试用一个延迟命令确认事件循环中的定时器能正常执行。

### 4.4 Shell 的实际权限远大于文件工具

文件工具受路径白名单约束，但 shell 在用户确认后可以访问整台机器。代码中的禁止命令正则只是减少误操作，无法构成边界；源码注释也承认这一点。

对于个人自用，这是一项明确接受的产品取舍。若以后交给其他人使用，应增加真正的进程沙箱、受限工作目录或可审阅的脚本执行层。

### 4.5 大文件和重复实现开始拖累维护（开始处理）

- `main.js` 仍混合窗口、托盘、桌宠、状态、IPC、对话和退出流程；设置存储和进程检测已经先拆到 `main/`，其余边界仍待继续整理。
- `renderer/chat.js` 约 74 KB，界面状态和 DOM 操作高度集中。
- `脑/人格.cjs` 已没有调用者，实际提示词由 `脑/提示词.cjs` 负责，但 `对话.cjs` 顶部注释仍说使用前者。
- 一些早期注释描述的功能状态已经与实现不一致。

现在还能依靠大量中文注释理解，但继续加功能会让修改影响范围越来越难判断。

### 4.6 测试对原机器布局的依赖（已处理）

测试现已通过统一配置指向临时干净工作区；需要历史数据的用例会自行构造并恢复夹具。命令失败用例也已改为确定性非零退出。当前本地核心测试共 523 项，全部通过；没有调用付费模型，也没有运行联网、语音、桌宠或 Electron 图形界面联调。

## 5. 建议的改造顺序

1. 从 `main.js` 继续拆出窗口、托盘、IPC 和外部服务模块。
2. 从 `chat.js` 拆出对话、附件、任务抽屉和确认卡。
3. 删除或合并已经失去调用者的旧模块，随后更新注释和测试说明。
4. 运行 Electron 图形界面、联网模型、语音和桌宠的整体验收。

## 6. 总体判断

这是一个已经跑通过真实使用场景的个人桌面 Agent，不是简单的角色聊天壳。它最有价值的地方是把人格、记忆、工具权限、语音和学习流程接成了完整闭环，而且大量注释保存了设计原因和踩坑记录。

当前的主要瓶颈不在功能数量，而在可迁移性与边界工程：它仍然默认只运行在这一台机器、这一组目录中，安全边界对普通路径处理得认真，但还没有覆盖文件系统链接和 shell 隔离。先解决这两类问题，再继续叠功能，项目会稳很多。
