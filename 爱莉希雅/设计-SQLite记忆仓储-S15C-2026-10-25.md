# S-15C：复用业务规则的SQLite记忆仓储

2026-10-25，基线`5f17a6e`。本轮仅C：长期/临时、证据/评分、确认与晋升事务。正式JSON/JSONL仍是权威，新SQLite仓储没有生产接线，D的关系图/日记/渠道未开始。

## 规则复用与附带修正

把原`脑/临时记忆.cjs`的常量、辅助函数及状态函数机械移动到`脑/临时记忆状态.cjs`。逐段比对与基线一致；纯状态引擎只接收同步读写、时间和编号提供器，无配置或文件依赖。原文件保留原路径解析、JSON读取/版本检查/原子替换和默认实例/公开接口，调用同一引擎；没有转换或批量重写现有记忆。

SQLite同样调用这套状态函数，复用归档、复活、关系冲突、人工替代/并存、修改/删除与晋升状态流。评分继续调用原`临时记忆自主评估.cjs`，正文/人物仍走原记忆结构和叙述函数；不是新增评分方案。`临时记忆晋升.cjs`也直接复用，只把长期写入适配为同连接SQL。

发现旧JSON长期写入虽已按60分升格，却仍用70分决定是否保存自主评估说明，导致60–69分说明遗漏。本轮改为同一自动阈值常量并补测试，只保留已经批准的评分信息；不改分数算法、不降低其他门槛、不回填历史正文或评分。

## 同一连接中的数据

`storage/sqlite-memory.cjs`使用B的显式内存上下文和会话表，不开第二份正式库。

| 表 | 保存及约束 |
|---|---|
| memory_temporary | 稳定编号、完整原结构JSON、生命周期/确认/到期投影；按插入顺序读取以保留旧状态引擎的同时间顺序 |
| memory_evidence | 临时编号外键、指纹及证据次序、逐字证据完整JSON；同记录同指纹唯一 |
| memory_assessments | 临时编号外键、历史次序与完整评估JSON |
| memory_long | 类别＋编号主键，来源临时编号唯一，完整长期JSON；同一临时不能重复写到两个类别 |
| memory_operations | 操作编号唯一、类型/规范输入指纹、回执JSON与校验哈希；版本与操作数一起提交 |
| memory_tombstones | 删除临时的时间及完整末态JSON，供后续迁移/回退审计；不进入普通查询 |
| memory_long_deleted | 类别＋编号的长期删除档案；普通列表排除，旧晋升不能将其自动重建 |

七张业务/内部表，版本保存在共享repository_meta中。证据和评估历史随临时删除级联清理；晋升来源允许指向明确删除档案，保留原追溯信息，不把它冒充仍有效记忆。删除档案不是私密日记，也不是新增UI“撤销”功能。

## 接口与原子性

每个变更输入必须含稳定操作编号、明确UTC时间、预期记忆库版本。版本用于整个记忆工作单元，防止旧审核覆盖任何较新的记忆变化；不与B的会话设置版本混用。输入只接收有大小/深度限制的纯JSON数据，不执行getter/toJSON或丢弃非法值。

| 接口 | 内容 |
|---|---|
| 新增临时 | 默认模型候选，必须有B已保存的user消息及逐字依据，当前来源会话允许长期记忆；保留原默认天数，自动入口不能延长；显式手动分支保持原1–30天/默认确认规则 |
| 评估并晋升 | 输入候选编号与消息编号，从B读取原话/时间并复核开关；调用原评分，低分也保存证据，达到60分且无冲突才确认及晋升 |
| 人工处理临时 | 复用旧修改/删除、提议/决定替代、归档/恢复、提议/决定晋升方法；不开放外部指定评分的自动确认命令 |
| 人工确认晋升 | 复用原确认/批准/长期写入/完成标记流程，整批提交；冲突必须先明确处理 |
| 新增长期/人工修改长期/人工遗忘长期 | 三类存取，以类别＋编号定位；修改保留最初时间/来源/评分，另记修改信息；遗忘留内部删除档案且排除普通列表 |
| 读取/查询临时、列长期、取统计/核验 | 返回副本、明确版本与截断信息；统计不含正文，核验表结构、外键、投影/次序、晋升目标及回执一致性 |

评估的一组变化可能依次写证据、历史、确认、批准、长期目标和完成标记；这些中间写入都在同一个BEGIN IMMEDIATE内，操作回执和版本最后一起提交。任何中途SQL失败整体回滚，不留下半确认或只写入长期的状态。提交/回滚不确定时沿用B的unknown及封闭能力，禁止继续读写或盲目重做。

同操作编号同规范输入返回原回执，不重复记账/晋升；同编号异输入拒绝。重放回执表示那次操作曾提交，版本是当时版本，不保证目标目前仍有效；读取当前列表判断现状。明确人工遗忘后，新的旧候选晋升操作报TARGET_FORGOTTEN，不复活被遗忘目标。

自动入口拒绝助手消息、无来源、非逐字依据、敏感/工具内容、非当前关系和过期有效候选。归档候选必须有新逐字依据才可复活，继续使用原证据指纹、100项证据/50项历史与保留期规则；原话不作为指令。来源时间保留，证据登记次序不冒充事件时间线，不猜旧未知时区。

归档时还没有账本的候选，仅以可验证原消息计一次历史提及基数；该原来源指纹不能再当新消息重放复活。真正的新提及继续走原评分，不批量为无来源旧候选补分。

手动接口及手动标记只表示内部调用意图，不是鉴权令牌；E接线时必须从受控人工入口与自动入口分别调用，不能把模型字段直接透传成手动命令。当前没有IPC、模型工具或渠道对这些接口的调用。
